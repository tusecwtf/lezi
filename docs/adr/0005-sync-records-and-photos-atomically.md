# 护理记录、护理计划与照片原子同步

带照片的护理记录及其全部记录照片构成一个记录同步包。发送端先把照片上传到 NAS 暂存区，最后才发布记录与完整照片引用；接收端先把记录和全部照片下载到本机暂存区，全部成功后才一次性写入并显示。中断时新记录不可见，编辑同步则继续显示旧版本，并在下次前台同步重试；产品不展示“记录已存在但照片仍是占位图”的部分状态。

护理计划与全部计划照片同样构成原子计划同步包，不采用“计划元数据先行”的提醒例外。接收设备只有在计划和照片全部就绪后才能显示计划并安排提醒；照片同步失败时不得暴露部分计划。

原子同步不阻塞创建者本机保存：本机数据与照片完整时立即可见，但在发布成功前标记“仅本机 · 等待照片同步”或“同步失败”，并明确其他成员当前不可见、不会收到计划提醒。创建者本机的系统日历副本和提醒不受 NAS 发布失败影响。

## NAS 协议（实现要点）

- 能力：`GET /health` → `capabilities` 含 `atomic_bundle`；客户端不得对缺失能力的 NAS 静默走 metadata-first。
- 发送：`POST /v1/bundles` 暂存根实体与媒体清单 → `PUT .../media/{uuid}` 上传字节 → `POST .../commit` 单事务发布。
- 根类型通用：`record` 与 `care_plan` 共用同一 bundle 契约；旧 `/v1/push`+`/v1/media` 仍兼容头像与旧客户端。
- commit 前实体对 `GET /v1/pull` 不可见；重复 commit 幂等；编辑在 commit 前保留已发布完整版本。
