# 将未来护理计划与已发生护理记录分离

未来时间的输入保存为护理计划，而不是提前写成护理记录，避免尚未发生的事项污染时间轴与汇总。护理计划到点只提醒，必须由用户明确履行后才产生一条关联的护理记录；录入、安排与履行复用同一面板的不同模式。护理计划属于家庭共享数据，任一成员履行后全家看到相同的完成状态与关联记录；计划可在用户授权后单向投影到 Android 系统日历，但系统日历副本、权限与提醒设置只属于当前设备，乐记始终是权威来源。

## Consequences

- 每台设备单独决定是否把家庭护理计划写入自己的系统日历；单条计划的本机投影选择不随家庭同步。
- 被动收到家庭计划时不索要系统日历权限。只有用户在当前设备主动开启系统日历同步后，后续收到的计划才自动建立本机副本。
- 同一护理计划出现多个履行结果时，在家庭同步阶段选出唯一的事实记录；先比较提交者身份（管理员优先），再比较不可编辑的履行确认时间（较早者优先），最后以 UUID 稳定排序兜底。可编辑的实际发生时间和受联网顺序影响的 NAS 到达时间均不参与裁决。
- 裁决落选的履行结果标记为“冲突未采纳”，不进入正常时间轴、汇总、搜索或普通导出，但在计划同步历史中保留提交人与内容；管理员可将其转为一条独立护理记录。
- 所有已开启的具体记录项目（含具体自定义项目）都可创建护理计划；安排计划不提前启动母乳计时、睡眠或其他持续状态，这些状态只能在履行时开始，并在形成实际护理记录后完成计划。
- 编辑既有护理记录并把时间改到未来时不得静默改变事实语义；用户确认“转为护理计划”后，原记录软删除并移出时间轴与汇总，原字段、备注和照片进入新计划，记录 tombstone 与计划共同参与家庭同步。
- 把既有护理计划的计划时间改到当前或过去只会使其成为“已错过”，不得自动生成护理记录；只有用户执行“完成并记录”并确认实际发生时间，计划才算履行。
- 任意家庭成员都可创建护理计划并履行任意成员创建的计划。普通成员只能修改、跳过或删除自己创建的计划；管理员可管理全部计划。创建者离开家庭后计划继续保留并由管理员管理。
- 首版护理计划只表示单次安排，不包含每天、每周或间隔重复，也不向系统日历写入循环事件。
- 计划时刻由绝对时间与创建时区共同表达；家庭设备在同一瞬间提醒，设备时区不同时显示本地换算结果与原计划时区，实际护理记录仍使用用户确认的实际发生时间。
- 乐记日历不再新建自由标题日程；“＋”先选择具体记录项目，再进入统一的安排护理面板。历史 `CalendarEvent` 继续显示、编辑和提醒，只有用户明确确认时才转换为护理计划，不做自动迁移。
