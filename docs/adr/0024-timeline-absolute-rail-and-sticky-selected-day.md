# 一日时间条以绝对瞬时渲染，选中日由粘性规则推导

记录页一日时间条的**唯一渲染坐标是绝对瞬时**（epoch ms）：视窗是 `[start, start+duration)`，
段、午夜日界、小时刻度、现在线与手势都以 `(t − start) / duration × width` 映射到像素。
**选中日不再是几何原点**，而是松手/惯性结束后从视窗按粘性规则推导出的日历结果。

本决策取代 2026-07 起的「围绕选中日 D 维护 D−1|D|D+1 三本地日工作轴、以工作轴分钟数
渲染」的做法。产品合同见 [`docs/spec/contracts/ui.md`](../spec/contracts/ui.md) §3 / §5.2；
术语见 [`CONTEXT.md`](../../CONTEXT.md)「选中日」「时间轴历史浏览」。

## 背景

三日工作轴把「选中日」揉进了渲染坐标：换日必须重建工作轴、把同一绝对视窗换算成新的
分钟偏移。状态机保住了绝对视窗，但渲染层在分钟空间做 settle 动画、记录段又异步按新轴
重算，用户看到的是换日时整日横扫再弹回；为了让预览不出三日窗，又不得不加「一次手势一个
宽度、最多相邻一日」的硬限制，惯性被截断。今天实时吸附还把「松手未越过午夜」一律弹回
现在，今天上午的记录几乎无法停留查看。三者叠加就是「容易换天 + 大回弹 + 断裂」。

## 决策

1. **渲染只认绝对瞬时。** designsystem 时间轴组件不持有日历、选中日或任何「工作轴原点」；
   它接收绝对视窗、绝对段、绝对日界/刻度/现在，并只做像素映射与命中。日历几何（本地午夜、
   DST 空洞/重复、小时刻度）由 feature 层按视窗范围用 `ZoneId` 规则生成。
2. **换日零位移。** 提交选中日只改 TopBar/列表/汇总锚点与变浅范围；轨道像素不变、不重建
   坐标、不 settle。唯一的 settle 是回到实时吸附 `[现在−24h, 现在]`。
3. **无天数上限。** 跟手拖动向过去无限制，惯性可跨多日（摩擦调大），唯一夹紧是现在边界。
   记录按视窗覆盖的本地日 ±1 日缓冲加载，与选中日解耦。
4. **粘性选中日。** 松手/惯性结束：右边界到现在 → 今天并吸附；否则当前选中日在视窗中占比
   ≥ 1/4 → 保持；否则取占比最大的本地日（并列取较晚，≤ 日历今天）。实时吸附态恒为今天。
   不用视窗中心日、不用右边界日。
5. **今天也能停留。** 从实时吸附向过去拖后松手进入「今天的历史浏览」，停在原地；
   「返回今天 / 回到现在」按钮是回到吸附的显式入口。

## 取舍

- 放弃「视窗中心日」的直觉性，换来小幅试拖不换日、早晨实时视窗（2/3 在昨天）不误判。
  代价是视窗里最多 3/4 可能不是选中日，靠邻日变浅与日界日期标签补足。
- 放弃三日窗对数据量的天然上限，换来连续惯性；以「视窗覆盖日 ±1」量化加载键控制重查频率。
- 保留选中日只在 settle 提交，不做拖动中实时换日，避免列表/汇总在手势中反复重载。

## 后果

- `TimelineInteraction` 仍是纯 reducer：绝对视窗 + 现在夹紧 + 粘性提交；渲染层不得再持有
  第二套视窗策略。
- DST：占比、日界、刻度全部按真实经过时长与 `ZoneId` 规则，不合成 24h 日。
- 测试合同：换日提交前后绘制起点不变；早晨小幅拖动保持今天；多日惯性落在占比最大日。
