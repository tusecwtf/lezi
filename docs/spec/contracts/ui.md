## 1. 设计原则

1. **单手大按钮**：两套模板都固定底部快捷记录坞；槽序由用户编排的绝对左右序决定（不镜像惯用手），圆盘/表单可随惯用手靠边，喂奶计时圆钮刻意做大。
2. **先写入、后提示**：睡眠异常等用 `!` 标记，不拦截录入。  
3. **三层日信息**：时间条（节奏）→ 日汇总（合计）→ 时间轴（明细）。  
4. **可定制降噪**：图标显隐/排序；可关喂奶计时入口。  
5. **家庭数据、安静同步**：可信家庭服务器全量共享（同步域内）；**不**对每条对方记录推送；**打开/下拉/前台**才更新（见 [`sync-trusted-endpoint.md`](./sync-trusted-endpoint.md)）。
6. **无广告位**：布局不预留横幅广告条。  
7. **深色护眼**：菜单一键切换；夜喂低眩光。  
8. **多宝宝防误记**：每宝宝主题色；昵称/长按 Tab 切换。  
9. **辅助信息就近**：相对时间「N 小时前」、发热说明、平均睡眠等。  
10. **记录可回忆**：日记照片；后期 PDF/TXT。

## 2. 设计系统（Token）

### 2.1 两套等价模板

乐记提供两套本地界面模板；切换只改变视觉表达，不改变导航、记录类型、表单字段、计时状态、汇总口径、成长数据或家庭同步行为。

| 模板 | 设置文案 | 视觉语言 | 图表语言 |
|------|----------|----------|----------|
| `warm` | 温暖卡片 | 奶油底、8dp 圆角卡片、三条横向连续绝对时间轴；今天默认最近 24 小时，历史日默认完整自然日 | 圆角柱、简洁折线、留白优先 |
| `journal` | 紧凑记录簿 | 珊瑚顶栏、网格+分割平铺（少用卡片）、紧凑日志；一日时间条与 warm 共用连续拖动、换日与实时吸附合同（直角 panel）；**记录/汇总/成长主列左右 16dp（`LeziSpacing.Page`）留白对齐为内容列，底坞仍 full-bleed** | 事件点/睡眠块、密网格百分位线 |

- 默认模板为 `warm`；入口：菜单 → 显示 → 界面模板。
- 选择持久化在本机，并与深色模式正交组合。
- `journal` 的密度、层级与图表形态由 Compose `designsystem` 与各 feature
  实现固化，并使用乐记品牌和自有绘制组件。
- warm 与 journal 的顶栏宝宝强调、主 CTA 与选中态均使用当前宝宝主题色；journal 珊瑚只作为无宝宝主题时的模板默认色，不是 CTA 例外。
- 两套模板必须共享同一 ViewModel/domain/Room 数据流；禁止复制业务分支形成两套功能实现。

| Token | 规则 |
|-------|------|
| **主色** | 每宝宝 **主题色** 驱动顶栏、选中态、强调按钮 |
| **浅色表面** | 浅底列表 + 卡片 |
| **深色表面** | 全局深灰/黑；图标保持对比 |
| **语义色** | `!` 警告、体温偏高提示；睡眠/喂养在时间条上分段着色 |
| **午睡** | 汇总睡眠图中可用橙色区分（设置可开） |
| **圆角** | warm 卡片/按钮统一 8dp；journal 列表/分区 0（网格分割），按钮 8、弹层 18、圆形记录图标/计时/头像 |
| **触控** | 常规 ≥48dp；计时器按钮显著更大 |
| **媒体** | 照片统一压缩（建议长边约 1200～2000px，一档即可） |
| **字体** | 顶栏昵称/日龄强调；时刻中等；相对时间次级灰字；汇总数字突出 |
| **动效** | 主转场应迁到 `LeziMotion` 三档（见 §2.1.1）；迁移完成前允许既有毫秒字面量，**新**主路径优先 token |
| **结构密度** | 结构角色以 `LeziDensity` 为准（warm 更开敞 / journal 更紧凑，见 §2.1.1）；高优先面逐步替换，既有 `LeziSpacing` 结构值仍可用直至迁移 |

品牌色板自定（建议一组柔和、夜喂不刺眼的主题色 8～12 色，**全部免费可用**）。表面容器梯度（`surfaceContainer*` / `surfaceBright` / `surfaceDim` / `surfaceTint`）在四套 scheme 中全部由 `LeziColors` 单源经 `resolveLeziColorScheme` 解析，底部弹层/表盘等默认底色因此随暗色走品牌蓝黑（#15202C 系）而非 M3 紫黑；warm 明暗快照见 `design/tokens.json` `color.surfaceContainer`（0.5.4 票 13）。

#### 2.1.1 动效时长与模板结构密度

共享 token 在 `designsystem` 的 `LeziMotion` / `LeziDensity`（`Tokens.kt`）与 `design/tokens.json` 的 `motion` / `density` 快照，与既有 `LeziSpacing` **并列**；旧间距 token 可继续使用，高优先结构面逐步迁到密度表（记录面 06+）。Shell 主转场（主导航 / 顶底栏 / 布局编辑 / 引导步进）已迁到 `LeziMotion` + reduce-motion 解析（票 10）；其它叶子面允许既有毫秒字面量直至各自迁移。

**动效（`LeziMotion`，单位 ms）** — 词汇表供主导航淡入淡出、布局编辑、引导步进、内容交叉淡入、区间 Tab 反馈、主计时控件颜色反馈等主转场。Shell 路径须引用 token 与 `leziMotionMillis`；其它路径既有 `tween(durationMillis=…)` 字面量仍合法：

| 档位 | 常量 | 时长 | 用途 |
|------|------|------|------|
| Fast | `LeziMotion.Fast` | 150 | 微反馈、短退出 |
| Base | `LeziMotion.Base` | 200 | 默认进入/退出与内容交叉淡入 |
| Emphasized | `LeziMotion.Emphasized` | 300 | 较大结构转场（布局编辑、多步） |

系统「减少动态效果」开启时，产品以 `Settings.Global.ANIMATOR_DURATION_SCALE` 为 reduce-motion 源（Compose 侧经 `leziMotionDurationScale` / `LeziMotion.systemAnimatorDurationScale` 读取），非必要转场经 `LeziMotion.nonEssentialMillis` / `leziMotionMillis` 瞬时（0ms）；状态切换仍立即完成且可读。协程上下文上的 Compose `MotionDurationScale` 是同一系统信号的关联平台时钟，**不是** call-site API——布局拖动等路径已刻意走 `ANIMATOR_DURATION_SCALE` → `nonEssentialMillis`，禁止并行第二套时长表。主导航、顶/底栏、布局编辑与引导步进已接线（票 10）。

**缓动（`LeziEasing`，motion-polish 票 02）** — 入场 `LeziEasing.EmphasizedDecelerate` = cubic-bezier(0.1, 0.7, 0.1, 1)、出场 `LeziEasing.EmphasizedAccelerate` = cubic-bezier(0.3, 0, 0.8, 0.2)；值取 material-components-android 1.12.0 AAR 实际发货值（m3.material.io 早先文档与 AAR 有出入，以 AAR 为准），快照同步在 `design/tokens.json` `motion.easing`。缓动 token 只提供曲线、不携带时长——时长仍以 `LeziMotion` 三档为唯一来源，缓动调用点同样禁止内联 ms 字面量形成第二套时长表。页面级全屏 push 进入升 Emphasized 档 + decelerate、被覆盖面退出保持 Fast + accelerate、tab 切换维持纯 fade Fast（票 04）；微反馈沿用 tween 默认 FastOutSlowIn（恰为 AAR legacy 曲线），不另立常量。

**触觉（`LeziHaptics`，0.5.4 票 15）** — 结果确认类触觉统一经 `designsystem` 的 `rememberLeziHaptics()`：确认/拒绝语义在 API 30+ 用平台 `View.performHapticFeedback(CONFIRM/REJECT)` 补足（Compose BOM 只有 LongPress/TextHandleMove 两档），更低版本回落 Compose LongPress；两条通道都不传 ignore flag，始终尊重系统触觉设置。触觉是**离散提交动作的轻确认**（记录保存成功、删除确认执行、计时开始/暂停与保存完成、底部长按切宝宝），禁止挂到每帧/高频路径；既有滑动删除阈值（§5.2）与布局拖拽（§5.8）触觉点保持原样。

**冷启动首帧（motion-polish 票 01）** — 冷启动不得出现闪白/闪黑/错误屏三连跳：

- 系统启动窗与首个 Compose 帧共用同一背景色：`values/colors.xml` 的 `lezi_window_bg`（= `LeziColors.Bg`），`values-night` 覆写为 `LeziColors.DarkBg`；两处色值变更必须同步。
- `MainActivity` 经 core-splashscreen 桥接：`setKeepOnScreenCondition` 仅在本地数据门禁 `Checking` 期间按住系统启动窗；Snapshotting/Migrating/Blocked 立即释放给应用内进度 UI。无品牌启动页、无人为延迟（CONTEXT.md 本地数据升级门禁的 _Avoid: 启动页_ 仍生效——按住系统启动窗不属于启动页）。
- 深色口径全链路同源：门禁屏、主题、`leziDarkTheme` 都读 DataStore `darkMode` 设置，"system" 才跟随 OS；已知残余 seam：app 强制深色而系统浅色时，启动窗仍为浅色（资源限定符跟随系统），只允许这一处一次切换。
- `RootViewModel.ui` 未决（null）时根节点渲染主题背景空帧，**禁止**用 `RootUi()` 默认值渲染 Onboarding（否则老用户首拍闪现引导页）。

**结构密度（`LeziDensity`，4/8 网格；垫值引用 `LeziSpacing` Xs/Sm/Md/Lg）** — 同一结构角色 warm 更开敞、journal 更紧凑；长辈模式（l1–l3）用独立 `Elder` 表替换模板表。触控下限仍为 `LeziSpacing.Touch`（48dp）；elder 主操作经 `LeziThemeExt.touchTarget` 升到 60dp。`LeziSpacing.CardPad` / `TopBarHorizontal` / `SectionGap` 为单模板遗留值，结构角色迁移后以密度表为准：

| 结构角色 | Warm（开敞） | Journal（紧凑） | Elder（长辈） | 网格步 |
|----------|--------------|-----------------|---------------|--------|
| 卡片内边距 `cardPad` | 16 (`Md`) | 12 (`Sm`) | 20 (`Lg`) | 4/8 |
| 顶栏水平 inset `topBarHorizontal` | 12 (`Sm`) | 8 (`Xs`) | 16 (`Md`) | 4/8 |
| 分区间距 `sectionGap` | 16 (`Md`) | 8 (`Xs`) | 20 (`Lg`) | 4/8 |
| 面板内容 pad `panelContent` | 16 (`Md`) | 8 (`Xs`) | 20 (`Lg`) | 4/8 |
| 快捷坞外水平 inset `dockOuterHorizontal` | 12 (`Sm`) | 0（贴边） | 12 (`Sm`) | 4/8 |

Compose 消费优先 `LeziThemeExt.density`（或 `resolveLeziDensity`）。Elder 另经 `LeziThemeExt.structure` 覆写顶栏 min-height 76、坞槽 84、时间条小时轨 22、chips 两栏。高优先消费面：顶栏、三日本地日时间条 chrome、汇总图卡、确认面板与快捷记录坞结构间隙。Elder 辅助色由 `resolveLeziColorScheme(..., elder)` 对 `onSurfaceVariant` 加深派生，浅/深底正文与图标对比度 ≥4.5:1（大文本 ≥3:1）；非 elder 色值逐位不变。桌面小组件跑在 launcher 进程，`LeziTheme`/fontScale 不可达，明确不覆盖。
长辈 l1/l2/l3 在进程内用 1.5/1.8/2.1 **替换**系统 fontScale，不叠乘；关闭后跟随系统。时间条小时刻度在长辈下用短时标（`00` 而非 `00:00`）；相邻刻度至少留 8dp（`LeziSpacing.Xs`），避让时宁缺勿叠。顶栏宝宝区、日期区、搜索之间至少 8dp。上述间距与不重叠合同对 warm / journal × l1 / l2 / l3 同时成立；可用竖屏宽度地板为 360dp（完整可读）。设备矩阵按**物理像素**覆盖 720p / 1080p / 1440p / 4K（最短边 720–2160px），每档竖屏都含 1.4:1 与 23:9 极端比例；测试必须带对应 density，禁止用 density=1 把 360.dp 画成 ~360px（300p 级）画布。矮屏保顶栏 / 坞 / 底栏互不重叠且中间列表区高度 > 0；超长屏不得把固定 chrome 拉出视口。`MainActivity` 与小组件配置页锁定 `portrait`：旋转手机不进入横屏、不因方向重建；分屏等系统强行改窗口不承诺。


### 2.2 单手操作契约

- `warm` 与 `journal` 共用同一固定底部快捷记录坞，不允许某一模板退化为滚动列表末尾入口。
- 默认右手；可在“菜单 → 显示设置 → 单手操作”切换左手，偏好保存在本机。
- 快捷记录坞固定为四个用户自定义记录槽位和一个不可关闭的“更多”入口；四槽按用户编排的**绝对左右序**展示（左→右为槽 0…3，再接「更多」），**不**随惯用手整体镜像。惯用手仍作用于圆盘调时与表单靠边等 chrome，不决定坞槽序。
- “最高频”只约束用户编排与可达性，不代表选中态；所有无真实交互或领域状态的空闲槽位使用同一中性容器，记录类型仅由名称、图标和类型色区分。
- 四个槽位可绑定任一已开启的内置记录项目或未删除的自定义记录项目；槽位绑定项目身份，自定义项目改名或换图标后同步更新显示。
- “更多”不能占用常用槽位；睡眠等有状态项目进入槽位后仍按自身状态切换动作与文案。
- 关闭或删除占用常用槽位的项目时不自动替换；原位置如实显示“空槽”。日常触摸短按为空操作，不声称会选择项目或直达设置；长按、读屏“编辑常用布局”动作或硬件键盘 Enter 进入同一个布局编辑态。
- fresh install 以尿尿、睡眠、母乳、配方奶作为四个常用槽位的初始值。
- 点击任一快捷槽位后先打开对应的预填二级确认面板；未确认不得写入。
- 母乳、奶瓶、睡眠及“更多”中的全部项目统一进入类型专属二级面板，均包含基本信息、备注、点击时刻与圆盘调时；确认后才写入。
- 睡眠二级面板按全局未结束睡眠切换“确认睡下 / 确认醒来”；睡眠进行中头像显示月亮睡帽。非长辈顶栏正文「{昵称}睡觉中」；长辈模式正文只显示昵称，睡觉态由月亮睡帽表达，TalkBack 仍读「{昵称}睡觉中」。
- “更多”从固定入口打开可滚动的四列底部项目面板；所有项目热区至少 48dp。
- 完整记录表单允许滚动，但“保存”始终固定在底部且为全宽按钮。
- 搜索、换日、删除等低频或高风险操作可以保留在顶部，不占用拇指区的主记录入口。

选中日只在松手或惯性结束后提交；拖动/抛滑过程是预览，轨道内容按绝对时间连续跟随，不因任何提交而位移。

**粘性选中日规则**：设 `share(day)` 为本地日 `day` 在当前视窗中占据的时长比例（按本地午夜切分，DST 日按真实时长）。松手/惯性结束时依次判定：

1. 右边界到达现在 → 选中今天并实时吸附。
2. 否则若 `share(当前选中日) ≥ 1/4` → 保持当前选中日与绝对视窗。
3. 否则选中日 = `share` 最大的本地日（并列取较晚一日），夹紧 ≤ 日历今天；绝对视窗保留。

实时吸附态恒为今天，不参与 2/3。阈值 `1/4` 是单一常量，按视窗时长计算；不用视窗中心日、不用右边界日、不限制一次手势能跨的天数。

| 起始状态 | 松手位置 | 结果 |
|---|---|---|
| 历史浏览（包括今天但尚未实时吸附） | 当前选中日仍占视窗 ≥ 1/4 | 保持 D 与绝对视窗 |
| 历史浏览 | 当前选中日占视窗 < 1/4（含惯性跨多日） | 选中日改为占比最大的本地日，保留绝对视窗，轨道不动 |
| 历史浏览 | 右边界到达现在 | 选中今天，settle 到 `[现在−24h, 现在]` 并开始跟随 |
| 今天实时吸附 | 向过去拖后松手，右边界未到现在 | 进入今天的历史浏览，停在松手处；选中日按 2/3 判定 |
| 今天实时吸附 | 向未来拖 | 在现在边界夹紧，保持实时吸附 |

举例：今天 08:00 的实时视窗为昨天 08:00 → 今天 08:00，`share(今天) = 1/3`；左拖 2h 松手仍是今天，不弹回；继续拖到右边界早于今天 06:00 后 `share(今天) < 1/4`，选中日变为昨天，轨道像素不动，只有 TopBar/列表/变浅范围更新。

**返回今天 / 回到现在**：时间轴处于历史浏览时，时间条下方显示整宽次要按钮——选中日 ≠ 日历今天写「返回今天」，选中日 = 今天写「回到现在」；点按选中今天并 settle 到实时吸附。实时吸附时按钮不显示。

冷启动/进程重建：选中今天恢复实时吸附，选中历史日恢复该日完整自然日。日历今天（设备时区本地日历日）由 Root 在每次回前台和前台下一个本地午夜重采；当时选中日等于旧的日历今天则滚到新的一天并实时吸附，浏览更早的历史日则保持该日。进程重建同时恢复选中日与当时的日历今天：二者相等视为「当时在看今天」；缺当时的日历今天则只夹紧已存选中日，不把昨天当成「当时在看今天」。切换 Tab、旋转和短暂后台期间保留历史浏览的绝对视窗。时间条不新增 TalkBack/键盘自定义换日动作；不能或不便横拖时用 TopBar 的前一日、后一日和日期选择（今天后一日保持禁用）。「返回今天」与月历「回到今天」以刷新后的日历今天为目标，不得用过期 today 夹紧。

## 5. 页面规格

### 5.1 启动引导

启动引导和账户未加入态复用同一个家庭认证状态机。首启仍可直接选择**离线使用**，本机建宝宝
后进入主屏；以后从账户连接家庭服务器。

#### 家庭认证唯一流程

```text
连接家庭服务器
  -> HTTPS trust（系统 PKI 或管理员确认 TOFU 指纹）
  -> setup-status probe
     -> empty：新建家庭（根密码）
     -> configured：加入家庭
        -> 我是家庭管理员（根密码；可显式接管）
        -> 我是家庭成员（申请审批或管理员单次 QR）
  -> 耐久保存设备 session
  -> 首次完整同步
  -> 结果
```

- 不在连接前选择新建/加入；不输入或读取 Wi-Fi/SSID。
- 任一步均可「暂不连接，保持离线」，不破坏 Room 待对账修改、已可信 endpoint 或有效 session。
- 管理员不扫码登录。普通成员 QR 同时携带 endpoint trust 配置与目标 membership 的十分钟
  单次授权，服务器不生成 QR 图像。
- 根密码、QR grant 与 access token 不进入可恢复 UI state；首次同步失败保留已签发 session，
  只重试同步。
- 成员手动申请进入「等待管理员确认」，可以继续离线；批准后下次前台检查完成登录。
- 「待同步 N 项」按尚未取得家庭同步终态的原子单元计数，不按 Room 行数或照片数累加；只有
  完整权威裁决落库后才能显示「已同步」。
- 无法进入家庭权威图但必须保留的用户事实显示「请选择家庭宝宝」或「等待管理员创建宝宝」等
  可行动本机保留状态，不混入家庭待同步数量，也不以清零为由静默删除。

完成家庭登录后的宝宝投影仍遵循家庭权威宝宝合同：Owner 可创建/管理；普通成员只读并等待
Owner。详细页面、错误和删除恢复见
[`可信家庭认证与同步 UI/UX 设计`](../../design/2026-07-30-trusted-sync-onboarding-ui.md)。

### 5.3 喂奶计时（全屏）

- **Composer→Timer 草稿所有权转移（非隐式放弃）**：从 Composer「开始计时」进入喂奶计时是显式 seed/ownership handoff，不是先关闭草稿再丢四个标量。可转移字段（宝宝、护理计划、备注、奶量、照片顺序与每张 borrowed/Composer-owned 所有权）在 Timer **确认接管** seed 之前不得被 Composer cleanup；导航失败或接管冲突时原草稿与照片保持可编辑。Timer 完成后 Composer-owned 导入归 Record；Timer 显式丢弃时回收 Composer-owned 文件；CarePlan borrowed 照片永不因草稿/Timer 丢弃路径物理删除。已填写但无法映射到计时的时长/顺序/时间须先明确确认。seed 照片与计划当前照片在完成时去重并限制 0–3 张；超限在离开 Composer 前提示删减。

- 左 / 右两大圆：开始、停止；累计分钟。  
- 中央：上次停在哪一侧。  
- 底部“完成并记录”只冻结点击时的左右时长与结束时刻，再打开确认面板；面板可调整时长、仅左（`L`）/仅右（`R`）/先左后右（`LR`）/先右后左（`RL`）顺序、可选奶量、备注和圆盘时间，确认后才写入。
- 从带图护理计划启动计时时，完成写入在提交前读取计划当前照片，并在 domain 事务内按序 clone 到护理记录（独立媒体行、共享本机路径）；不依赖确认面板上的照片草稿。计划侧照片与顺序保持不变。
- 计时中可进其它页；状态持久。  
- **返回策略采用后台继续（B）**：顶部返回与系统返回共用同一决策；已有累计或正在运行时离开详情页，并明确提示“计时仍在后台继续，可从通知返回”，不停止 FGS。只有页面内“丢弃”及其确认会销毁本次会话。Saving、保存后的 timer clear，以及未完成的下次喂养流程期间返回均被门禁并说明原因。
- 左右圆钮发起计时后，系统真实确认前台服务才显示运行；通知权限开启时还须确认通知已发布，通知权限关闭不伪造失败。系统拒绝时保留累计值和目标侧，明确显示已暂停并提供“重试启动”。
- 重开 App 不把未确认或已失联的服务伪装成运行中；这类会话显示为可恢复暂停态，由用户显式重试。
- 设置关闭后：记录页不显示计时入口。
- **计时完成态恢复（VM/`SavedState` 单主）**：确认面板的 draft、Saving/error 与提交身份（`completionClientUuid` + baby）由 `TimerViewModel.completionUi` 驱动并写入 `SavedState`（与 timer DataStore 解耦，避免 fail-closed 空会话与 Saving 脱节）；配置重建后任意新 composition 只订阅该状态恢复 sheet 与 busy，不依赖旧 composition 的 `remember` 或一次性 `onDone`/`onError` 回调。保存进行中再次确认保持同一 Saving，不启动第二个 coroutine/Record。domain 成功后立刻发布 next-feed offer（单 blob）或 pendingExit，并同时持久化 `timerClearPending`；按稳定 session token 停服和清空 timer DataStore 成功后，offer 才可交互、exit 才可消费。清空失败自动重试且返回/新计时保持锁定。失败回到可重试 sheet（含会话失效）。进程死亡后靠 durable `completionClientUuid` 幂等恢复，不重复 Record、候选、照片或 next-feed offer。Host 确认消费 exit 后重新订阅不得重复导航。

#### 事实后的下次喂养安排（唯一权威流程）

- 普通母乳、配方奶、挤出乳 Composer 与喂奶计时完成入口只在喂养事实事务成功后，进入同一套可选“安排下次喂养”流程；履行已有护理计划产生的事实不再递归提示。
- 事实与计划是两个保存边界：此时 Record 已经发生并持久化；“不安排”、计划保存失败或退出提示均不得删除、回滚或改写该 Record。
- **Composer 恢复顺序（先事实成功，再可恢复地选择计划）**：domain 写事实成功后立刻（1）把 fact message、baby/type、suggested time 写入 ViewModel/`SavedState` 统一 pending offer，（2）消费 restorable Composer request/draft，使进程重建不会重放 New 写事实；随后任意新 composition 只订阅该 observable post-save 阶段呈现/消费 offer，不依赖旧 composition 闭包改本地 `rememberSaveable`。非喂养保存同样经 observable finish message 只展示一次结果。共享 `LeziNextFeedPlanFlow` 仍负责 schedule 成功丢失后的核对、Skip 与配置重建相位。
- **计时入口**与 Composer 共用同一 `LeziNextFeedPlanFlow`；计时侧 pending offer / baby 身份挂在 `completionUi` + `TimerCompletionSavedState`，与确认 sheet 同一 observable 阶段，不另起 Compose 本地 `rememberSaveable` 双主。
- 默认时间按“护理间隔”设置从当前时刻推算。两个入口共用同一日期/时钟输入和未来时间校验；用户可调整后安排，也可明确选择“不安排”。
- 计划保存中禁用调整、重复提交与退出动作。保存回调失败、丢失，或重组/进程重建恢复到
  未决写入时，不得直接把它当作“未安排”：两个入口通过同一持久化核对 seam 查询该宝宝的
  开放下次喂养 marker，核对期间禁用“不安排”、重复提交与完成。查到 marker 后采用数据库
  中的计划时间并收敛为统一“已安排”结果；确认不存在后才显示“记录已保存”、保留用户选择
  的时间并允许用同一稳定计划身份重试或选择“不安排”；查询本身失败时只允许重新核对。
  协程取消原样传播，不伪装成不存在，也不重复事实或计划。
- 计划成功后两个入口使用同一完成反馈；只有用户确认成功或选择“不安排”后，才清除待处理身份并退出流程。

### 5.7 账户（目标行为）

账户面向小白，家庭卡与宝宝区分开。身份术语见根目录 `CONTEXT.md` 和
[ADR-0011](../../adr/0011-root-admin-and-multi-device-membership.md)。

#### 账户概览

| 区块 | 行为 |
|------|------|
| 家庭 | 家庭名、我的家庭称呼（Owner 标 ★）、一句浅同步结果 |
| 成员入口 | 「家庭成员与设备」；Owner 同行显示开放设备登录申请数量角标 |
| 待处理 | 已加入家庭且存在未解决并发分支 **或** 可处理未对齐项（本机多出、家里没收下、拉取洞）时，浅同步状态行显示「待处理 N」；点徽章或「N 项未收下」进入同一底栏。branched 冲突仍走 choice-only 全家裁决；未对齐项走本机去掉，不伪造 `conflict_id`。稳定墓碑、空分支集合不是同步冲突 |
| 宝宝区 | **唯一**宝宝管理面：单一列表（无「当前大卡」重复）；当前宝宝仅用主题色描边标识；点卡设为当前；⋯ 打开编辑/本机（含主题色与排序）/ 合并 / 删除；Owner 可添加；member 仅本机节 + 切换 |
| 未连接 | 「连接家庭服务器」；进入 §5.1 的 probe 驱动流程，可随时保持离线 |
| 页面底部 | member：退出这台设备 / 退出家庭；Owner：退出这台设备 / 删除家庭 |
| 家庭网络设置 | 所有已加入角色可进入；位于「退出这台设备」上方 |

账户概览不展示 IP、端口、token、server ID、trust mode、登录历史、独立同步卡或三步技术
教程；连接地址只在独立「家庭网络设置」子页显示。

全局冲突收件箱按服务器 receipt/update 时间降序、稳定 conflict ID 打破平局；每项显示根类型、
宝宝，以及本地已知的稳定 actor（目录缺失时原样显示 membership ID）。完整详情尚未缓存时
不渲染那些未知字段，收件箱整体显示正在获取详情，不得把未知误报为无删除候选或 0 张照片；
完整缓存存在后才显示精确摘要。家庭入口与 Record 时间线上下文入口只传
`conflictId` 给 app-shell 的同一 resolver。离线或无 ACL 的成员仍可审阅完整缓存快照，但提交
保持禁用。

冲突详情是全屏对照，不是底栏 sheet。稳定版与每个分支各一张产品卡，展示采用后时间轴/档案会看到的内容（类型、时间、摘要、备注、照片数、家庭称呼）；卡顶用精简产品字段写「不同：备注、奶量」，摘要里对应词加重。不展示 UUID、schema、membership id、设备 id、epoch，也不写本地/远程或设备称呼；来源只写家庭称呼，目录对不上则「家人」。卡上时间只留事件时间。进来默认选中当前稳定版。主操作是整版选择：点一张卡即按该版填满全部 conflicting path 的 choice id，不提供字段 radio。底栏跟所选卡：活版「采用这一版」只给家庭管理员（分叉后作者不能把一版写成全家新稳定）；有现成编辑器（记录/计划/宝宝）才给「采用并修改」；删除版「删除这条」并一次确认。本 membership 提交过 open 分支时另给明确动作「撤回我的修改」，家庭管理员另给「撤回这些修改」可一次清任意分支，都不是字段 radio「移除」；撤回不动家里正在用的稳定版，摘空后冲突自动已解决；还剩别人的分支时留在本页刷新对照，不报已解决。同步冲突收件箱不再提供「恢复删除前 / 恢复并修改」作为冲突主路径。采用并修改先 CAS 解决，再挡住等待随后 pull 把本机根换成选定版，然后打开已有 Composer / 计划编辑；取消等待不撤销已解决。服务器 Accepted 即可离开；不等本机随后 pull，也不等其他设备。自动合并内容不单独列出。缺选或服务端 incomplete_choices 留在本页说明，不要求重新打开。

#### 家庭网络设置

- 展示当前 HTTPS 地址、`可连接/暂时不可连接/安全信息已变化/正在检查`、最近健康时间与
  「更改地址」；不提供“立即同步”，也不展示 token、server ID 或登录历史。
- 地址输入是候选草稿。TLS、`/health`、`/ready` 与 setup probe 通过前不写现有配置；取消、
  失败或进程中断原样返回旧家庭。
- 自签名证书变化先显示旧/新指纹，再明确二次确认；确认信任不等于登录，下一步仍重新登录或
  申请审批。候选 configured 家庭 ID 不同则阻断。
- empty 候选只有旧 Owner 显示「从本机恢复家庭」；展示恢复宝宝/记录/计划/照片数量摘要、
  新服务器根密码与最终二次确认。普通成员不显示入口，两个已有家庭不提供合并。
- 离线时成员管理、退出/删除与更新检查显示明确不可用提示，但记录、计划、照片、计时、汇总、
  成长、搜索和系统日历投影继续工作。

#### 家庭成员与设备

- 账户概览的家庭名是只读展示；Owner 只从本页修改共享家庭名，概览卡不提供伪可点击改名入口。
- 成员入口在读取时显示加载状态；读取失败保留既有名单并提供点按重试，不以永久「查看家人」掩盖状态。
- 按 membership/家庭称呼分组；一个 membership 可有多台独立凭证设备。
- 所有成员看见成员称呼；普通成员只展开自己的设备并可改设备称呼、申请改家庭称呼。
- Owner 查看全部设备和最近使用，处理开放设备登录申请/改名申请，添加/改名/删除成员，生成
  目标 membership 单次 QR，重命名或撤销设备；已批准未领取的申请显示「等待设备领取」，
  并只提供撤销批准以释放称呼保留。
- 家庭称呼规范化后在当前家庭内唯一；新设备同名只能由 Owner 明确绑定，不能自动登录。
- 设备名默认 Android 设备名，只在同一 membership 中唯一。

#### 删除和退出

- 撤销/退出一台设备只删除该设备；主动退出在服务端确认后清本机。
- 删除成员/退出家庭彻底删除 membership、全部设备/凭证/申请并释放称呼；共享事实保留，作者
  置空显示「家人」。
- Owner 删除家庭需输入家庭名并重输根密码；成功后删除整个服务器家庭数据集。
- 普通凭证丢失或 401 保留本地记录并重新申请；只有明确
  `device_removed|membership_deleted|family_deleted` 才清本机家庭数据。

#### 时间轴与记录上传者

- 上传者 = 首次写出护理记录的 membership；同 membership 多设备都属于「本人」。
- 改名后历史展示当前称呼，不保存称呼快照；membership 删除后显示「家人」。
- 时间轴仅在上传者不是当前 membership 时显示对方称呼；未加入时不显示上传者。

护理计划提醒或新建立的系统日历副本。

“记录设置”只保留分项目参数与护理计划/日历；**常用四槽与所有记录布局**在记录页长按坞进入的**布局编辑态**中编排（全屏图标网格 + 跟手拖放，非设置二级长弹窗）：

1. **布局编辑态（记录页）**：进入后全屏替换记录页并隐藏日期 chrome 与主导航 tabs，只保留“编辑布局 / 帮助 / 完成”；目录以当前“添加记录”为视觉权威，共用分类标题、四列圆角记录卡片、柔色图标底板、字号、间距和 warm / journal 主题 token，且不重复“常用补充”。分类标题自身是长按拖动排序入口，释放到另一当前可见标题只产生类别排序；拖回自身或越界无操作。没有可见项目的普通类别不显示空标题，自定义类别即使为空仍保留标题和管理/新增入口。底部只表达四个常用槽与固定锁定“更多”，其顺序和几何与日常 Dock 连续；编辑空槽说明需从目录项目的操作中指派，“更多”保留可读的固定/锁定节点但没有编辑动作或键盘焦点。本机已删除是容量随可用视口和字体尺度受限的独立滚动区，界面标题为“已收起 · N 项”，辅助文案为“使用操作或拖出恢复”，不能无限长高、覆盖或挤出 Dock。编辑态目录卡片外缘填充透明，只保留柔色图标底板与标签。静止时沿用中性目录表面，只有合法拖入悬停才同时使用危险色、边框和“松开后收起，并清空常用槽”的文字/读屏反馈。编辑布局顶栏自管 status bar 避让，与日历/搜索/导出/计时共用同一全屏 chrome 合同。长按拖到槽可绑定/替换，槽间互换，拖出坞外清空快捷，拖入本机已删除会隐藏入口并清空所有指向它的槽；移出后恢复到所属类别当前可见末尾且不自动回填槽，释放在删除区内无操作。以上隐藏/恢复只修改完整设备本地布局快照，不删除历史 Record、家庭自定义项目定义或远端数据。读屏动作可完成指派、槽换位/清空、隐藏/恢复、类内排序和类别排序；键盘以 Tab / Shift+Tab 与普通方向键移动焦点，以 Ctrl+方向键排序/换位、Ctrl+1…4 指派、Delete 隐藏或清槽、Enter 恢复。读屏、键盘与拖动都只发出同一 `LayoutEditIntent`，经同一 reducer 和完整快照 writer 保存，不复制规则。类内落点排序；短按不写记录；“完成”或系统返回须等待最后一份完整布局快照耐久提交后才退出，失败时留在编辑态并提供重试；“正在保存 / 已保存 / 保存失败”只由 writer 当前最新快照状态播报，旧写入完成不得伪装为最新成功。项目只能在所属类别内排序，不能跨类别改变领域分类；类别序只写入设备本地 `DeviceLayoutSnapshot`，不进入家庭同步。自定义项目的新增/改名/换图标/删除可从编辑态「管理自定义」进入。
   目录项目与分类标题长按后，指针进入主目录上/下边缘带会按接近边缘的程度渐进自动滚动，离开边缘、到达内容边界、取消或放下即停止。快捷槽和本机已删除项目作为拖动来源时不带动目录滚动；指针进入本机已删除、四个槽、固定“更多”或 Dock 内部后，这些固定目标优先并立即停止目录滚动。自动滚动只更新当前可见落点，项目仍只能在原类别内排序，滚动本身不产生隐藏、恢复、清槽或投放 intent。
   清空常用槽或移入本机已删除的完整设备布局快照耐久保存成功后，显示一次短时原生“撤销”提示（默认约 4s，与 Material 短 Snackbar 对齐）；点击原生操作或在提示有效时按 Ctrl+Z 都提交同一个 exact token，并以完整 `before` 快照恢复。任一后续布局 intent（包括无变化 intent）、提示超时、退出或重进编辑态都会使旧 token 失效；原写入失败不得显示撤销，撤销写入失败则保留当前布局并提供同 token 重试，只有恢复快照耐久保存成功后才显示或播报撤销成功。不提供多级历史，且撤销仅作用于设备本地布局，不恢复或删除历史 Record、家庭自定义项目定义及远端数据。
   **布局撤销会话（VM 单主，跨配置重建）**：undo candidate、写入阶段（AwaitingOriginal / Available / Restoring / RestoreFailed）、token 序列与 offer 的**稳定 deadline**（`offerExpiresAtEpochMs`）由 `LogViewModel` 可观察会话持有，不依赖 composition-local `remember`。旋转或主题等配置重建后，剩余有效期内仍可撤销同一 `before` 快照；Snack 只展示剩余窗口，不得重建后重新计满。原写或 undo 写进行中时新 composition 继续投影正确 busy/result，完成回调挂在 ViewModel scope，不依赖旧 composition 的 coroutine scope。退出编辑态仍显式丢弃 available/failed undo；进程死亡 / 冷启动不承诺恢复——会话安全归零且不得逆写布局。
   编辑器静止时卡片、分类标题、本机已删除和 Dock 保持稳定，不播放持续晃动或无限动画。只有触摸拖动成功拾取、首次进入一个新的合法当前目标、以及布局 intent 确实改变当前快照的成功放下，才分别提供一次短视觉反馈和一次系统触感请求；同目标停留、no-op、自身落点、非法释放、取消及陈旧拖动事件不重复反馈。视觉脉冲作为不参与测量的覆盖层，不推动卡片或 Dock；删除区继续以危险文案、边框和语义区别于普通目标，而不只依赖颜色。系统动画缩放为 0 时反馈立即完成且拖放业务不变；系统关闭触感时不做补偿性重复请求，TalkBack 与键盘路径继续依赖既有可执行语义和状态播报，不伪造触感。
   旋转、系统深浅色或 warm/journal 等配置重建继续显示同一布局编辑会话，保留进入时宝宝/日期、当前完整布局与目录位置，并继续展示原 writer 的真实保存中、成功或可重试失败状态；半途拖动、当前落点、浮层与触觉/动效立即取消且不产生 intent。该会话标记和滚动位置只存在于配置重建可保留的本机 UI 内存中，不进入 `DeviceLayoutSnapshot`、数据库或家庭同步；force-stop、进程死亡与冷启动只恢复最后耐久布局并进入普通记录页，不自动重开编辑器。
   本机首次进入布局编辑自动在顶栏下方显示非模态短提示“长按卡片拖到常用槽；拖出槽位可清空。”，提示参与页面测量且不得覆盖目录、本机已删除、完成按钮或固定 Dock。主动关闭或第一次确实改变布局的触摸拖放在完整快照与完成标记都耐久写入成功后，本机记住完成并不再自动显示；no-op、取消、布局写失败、键盘或 TalkBack 替代动作不算首次拖放成功。配置重建保留当前提示的自动、手动或隐藏状态，真正冷启动按设备本地完成标记决定；标记不因主题、布局或自定义项目变化重置，也不进入家庭同步。顶栏“帮助”始终可重访同一权威提示，重访不清除完成标记。
2. **分项目设置**：只展示确有专属设置的项目。例如母乳包含计时入口、记录开始/结束与提醒间隔，配方奶/挤出乳包含剂量步进，体温包含婴儿发热提示；没有专属设置的项目不显示空入口。
3. **护理计划与日历**：配置本机“家庭护理计划提醒”（默认开）、是否在收到计划后自动建立系统日历副本、目标可写日历和三级披露；首次主动启用时才申请权限并选择日历，所有设置均不上传。

记录目录只显示当前内建类型与具体自定义项目；具体自定义项目直接显示为独立按钮。fresh install 的四个常用槽位使用当前默认或用户明确选择的具体项目。

### 5.9 搜索

搜索框 + 结果列表（复用时间轴 cell）+ 空结果文案。同一条非空查询还停在结果页时，记录、来源角色或当前宝宝变化会重读；不提供下拉刷新。

### 5.10 小组件

- 上：最近喂养 / 睡眠 / 排泄摘要与宝宝昵称（**产品有意暴露**，便于桌面一眼核对；仅 `home_screen`，非 keyguard）。  
- 肩窥残差为家用场景接受风险（访客桌面/投屏背景可能看到护理细节）；后续可选「仅快捷入口、隐藏摘要」开关。  
- 下：可配置快捷记录图标。  
- 每个 Widget 实例独立绑定宝宝与快捷类型；主题色可轻量体现。
- 快捷入口启动对应类型的预填 Composer；Widget 本身不得直接写记录。

### 5.11 护理计划日历

月历 + CarePlan 计划/提醒条目；CarePlan 可与家庭同步，系统日历配置只在本机。
本机提醒为**非精确**本地通知（与喂奶提醒同策略，见 [`platform.md`](../platform.md) §4）。

- 所有护理计划始终进入乐记日历；系统日历只是当前设备的可选单向副本。
- 乐记日历“＋”先选择具体记录项目并进入“安排护理”面板；不存在自由标题日程的创建、编辑或转换入口。
- 首次主动启用系统日历副本时申请权限并让用户选择可写日历，不静默采用默认账户。
- 三级披露首次默认预选“宝宝昵称 · 记录类型”，但必须由用户在授权流程中确认；后续修改只更新尚未发生的事项。
- 权限被撤销或目标日历消失时，计划仍正常保存并提示“未同步到系统日历”。
- 每台设备只发出一次提醒：系统日历副本与开始时提醒严格确认就绪时由系统日历负责；只有 provider 已确认释放/不存在时才由乐记回退，provider 仍持有已有提醒或结果不确定时保持单源并等待前台/重启恢复。
- 未来护理面板中的“同步到系统日历”默认开启；若本机尚未完成日历授权与目标选择，点按后进入设置流程，取消设置不阻断计划保存。

## 9. 失败文案（四段式目录）

可恢复失败的用户可见文案由 `core/common/failure/` 的 `FailureKind` →
`FailureCatalog` → `ProductUiError` 管线统一产出（0.4.8 ui-copy-hardening 交付；
原因透传以类型化异常优先，marker 匹配兜底）。

| 段 | 字段 | 要求 |
|----|------|------|
| 标题 | `title` | 短句；不出现内部枚举、黑话或技术细节 |
| 发生了什么 | `whatHappened` | 事实陈述，不猜测 |
| 可能原因 | `likelyCause` | 具体原因优先（类型化异常透传）；无可信原因才给通用候选 |
| 本机数据状态 | `localDataStatus` | 明确「已保存在本机 / 未保存 / 部分保存」，消除「数据丢了吗」焦虑 |
| 动作 | `actions` | 可执行按钮（重试 / 检查后重试 / 稍后再试 / 去设置等） |

- `FailureKind` 为闭合集合（25 类）：`AddressNotFound`、`Unreachable`、
  `CertificateChanged`、`SendStalled`、`ResponseTimedOut`、`HouseholdUnavailable`、
  `HouseholdSyncing`、`SyncTookTooLong`、`SafetyCheckStuck`、`AlbumReadStalled`、
  `SystemCalendarWriteFailed`、`ExportTookTooLong`、`HouseholdFactRejected`、
  `SessionExpired`、`AppUpdateRequired`、`ServerUpdateRequired`、`InvalidInput`、`TooFast`、
  `HouseholdStateChanged`、`QrExpired`、`QrWrongHousehold`、`ServerHasNoFamily`、
  `UnexpectedError`、`LocalSaveFailed`、`DeviceRemoved`；新增类别须同步本节。
- **禁令**：不新增「X 失败，请重试」式无原因、无数据状态、无差异化的模板句；
  IP、端口、token、server ID、内部枚举不进用户文案；信任不一致用独立阻断页而非
  普通网络错误（对齐 [`sync-trusted-endpoint.md`](./sync-trusted-endpoint.md) §7.3）。
- 各页浅状态行（`已同步 · …` / `已保存在本机 · 待同步 N 项` / `暂时无法同步 · 下拉重试`）
  见 [`sync-trusted-endpoint.md`](./sync-trusted-endpoint.md) §7.3，与本节目录互补不重复。

媒体身份按需门禁：只有照片缺少可信校验身份且已确认服务端未声明
`causal_media_identity_v1` 时显示 `ServerUpdateRequired`（「需要升级家庭服务器」）。
本机记录和照片保留，动作仅「先离线用 / 知道了」；不进入客户端 APK 强制更新壳。
声明支持却提供缺失或错误身份属于协议数据错误；无照片或可安全验证的旧照片流程不阻断。
