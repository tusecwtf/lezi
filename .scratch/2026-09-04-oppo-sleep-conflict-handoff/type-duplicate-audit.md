# 审查：0.4.7 会不会在同一时间点叠多条同类型事实

日期：2026-09-05 · 对照 tree `versionName 0.4.7` / `versionCode 28`  
问：同机连记、多机同时记，各 `RecordType` 会不会再撞出「重复」或「家里没收下」。  
结论先写：这不是 0.4.5 卡死雷的复发；是 ADR-0021 合同下的常态。服务器**不**按类型+时间去重。

## 总判断

库和 wire 的唯一身份只有 `client_uuid`。`(babyId, type, timestamp)` 是查询索引，**不是 UNIQUE**。

因此：

| 场景 | 会不会叠出两条同类型 | 用户看见什么 |
|---|---|---|
| **同一台 0.4.7**，同一次确认连点 | 不会。Composer `saving` 挡住；同一 `clientUuid` 幂等回放 | 一条 |
| **同一台 0.4.7**，开两次编辑页各确认一次 | **会**（睡眠开睡除外）。两次各发新 UUID | 两条独立事实，**不**进疑似重复（同 membership） |
| **同一人两台设备**（同一 membership）各记一条 | **会**。CONTEXT：同作者窗内多记不构成疑似重复 | 两条独立事实，汇总按两条计 |
| **两个人**（不同 membership）≤30 分钟各记一条白名单类型 | **会留下两条**；客户端组「疑似重复 · 待确认」 | 时间轴展开两边，汇总上下界；服务器不删任何一条 |
| **两个人各记一条睡眠** | **会留下两条开睡**。睡眠**不在**疑似重复白名单 | 较旧的标重叠待确认；「醒来」只打最新那条；**没有**疑似重复组 |
| 同 UUID 一边改一边已发表 | 不是叠两条，是 `content_drift` / `branched` | 「家里没收下」或冲突收件箱 |

0.4.7 **不会**因为同步引擎再「无中生有」塞第二条。叠两条的唯一来源是：**两次写入、两个 UUID**。

## 本机唯一会挡的：第二条开放睡眠

`addRecord` / `confirmSleep` 新开睡 / 睡眠计划履行：本机投影里已有开放 SleepStart → `SleepStateChangedException`。  
`sleepDown` 已开放时不插新行，只给现有条打 `anomaly_flag`。

同步拉进来的第二条开睡**不挡**：Ticket 06 / ADR-0021，较旧条 `isOverlapPending`，不自动闭合。

其它类型（含已闭合的睡眠段）本机**没有**「同秒同类型拒写」。

## 疑似重复白名单（跨作者、≤30 分钟、精确类型）

进组：`nursing` `formula` `pumped_feed` `pump_express` `baby_food` `snack` `drink` `pee` `poop` `both_diaper` `temperature` `bath` `medicine`

不进组：`sleep` `diary` `walk` `cough` `rash` `vomit` `injury` `hospital` `vaccine` `height` `weight` `head` `chest` `foot_size` `custom`，以及 WakeObservation。

喂养子类、排泄子类**不互并**：配方奶≠母乳，尿尿≠尿+便。

## 逐类型

### 喂养（白名单）

`nursing` `formula` `pumped_feed` `pump_express` `baby_food` `snack` `drink`

- 同机两次确认 → 两条。母乳计时器按 `completionClientUuid` 幂等，换 UUID 仍是两条。
- 两人同时记 → 两条都活；≤30 分钟出疑似重复。
- 风险：夜喂两人各记一瓶，不确认则汇总上下界；同人两台设备则**无提示、双计**。

### 排泄（白名单，子类不互并）

`pee` `poop` `both_diaper`

- 同机 / 多机行为同上。
- 风险：一人记尿尿、一人记尿+便，时间靠近也**不**进同一组，时间轴像两次换尿布。

### 体温 / 洗澡 / 用药（白名单）

`temperature` `bath` `medicine`

- 同机可叠；两人 ≤30 分钟进疑似重复。
- 风险：用药名/剂量不参与等价（CONTEXT：不看备注、剂量、照片），两剂不同药也会被提示「疑似重复」。洗澡一键，两人各点一次必进组。

### 睡眠（不进白名单）

`sleep` + 独立根 `wake_observation`

- 同机：挡第二条**开放**开睡；已闭合段可再记。
- 多机同时开睡：**两边都收下**。较旧重叠待确认；醒来快捷只绑最新。
- 多人可对同一条睡写多条 WakeObservation；有效观察指针另选。
- **这是今晚 OPPO 残局同构、且 0.4.7 健康设备仍会走的路径。** 不投影「家里没收下」，除非同 UUID 内容漂了。
- 风险：两条开睡撑时长；醒来打在新条上，旧条继续「进行中」。产品刻意不自动闭。

### 日记 / 散步 / 症状（不进白名单）

`diary` `walk` `cough` `rash` `vomit` `injury`

- 同机、多机都可以叠。散步/症状是一键，最容易两人各点一次。
- 风险：**无**疑似重复提示，汇总按两条计。日记叠两条通常可接受。

### 就医 / 疫苗（不进白名单）

`hospital` `vaccine`

- 同机、多机都可叠，无组。
- 风险：两人各记同一针/同一次就诊，时间轴两条、无提示。频次低，靠人看。

### 成长测量（不进白名单）

`height` `weight` `head` `chest` `foot_size`

- 成长页 `addRecord`，无「同日同指标只留一条」。
- 风险：两人同一晚各称一次体重 → 曲线两个点，无组。头围/胸围/足长不进趋势，只占时间轴。

### 自定义（不进白名单）

`custom`（具体项目最多 10 个）

- 同项目、不同 UUID 可无限叠；疑似重复按 wire 类型，`custom` 整类排除，**不**按自定义项目再分组。
- 风险：两人同时记同一自定义项（例如「维生素 D」）→ 两条、无提示。

### 计划履行（另一条冲突面）

任意可计划类型履行后写出一条护理记录。

- 同一 `clientUuid` 幂等；睡眠履行仍受本机开睡门。
- 两人履行**同一条计划**：走履行候选 / 「冲突未采纳履行」，不是疑似重复组。落选可转独立记录。
- 风险：和手记近邻叠在一起时，手记进疑似重复、履行冲突另走收件箱，用户可能看成两套「重复」。

## 0.4.7 还剩的风险点（按可感程度）

1. **多机同时开睡**（最高，与今晚残局同构）：两条开睡并存、无疑似重复徽章、醒来只打最新。健康 0.4.7 就会发生，不需要卡死。
2. **同人多设备连记白名单类型**：不进组，汇总双计（妈妈两台手机各记一瓶奶）。
3. **不进白名单的类型双记**：日记以外的散步/症状/成长/就医/疫苗/自定义，无提示。
4. **排泄/喂养子类不互并**：尿尿 vs 尿+便、配方奶 vs 母乳，近邻不提示。
5. **用药只看类型+时间**：不同药也会进疑似重复。
6. **同机两次打开编辑页**：挡的是连点，不是「同秒同类型」。
7. **同 UUID 漂移**：仍会「家里没收下」。这是合同，不是叠两条。

**不是风险：** 0.4.5 全量第二页卡死、generation 重启把 0.4.7 再卡死、服务器按时间自动删近邻。这三项当前 tree 都不成立。

## 和今晚 OPPO 事件的关系

今晚那条是 0.4.5 卡死期间两边各自写，0.4.7 拉通后显形。  
若全家都已是 0.4.7：同步不会再冻；**两人（或两台机）同时点「睡下」仍会留下两条开睡**。那是合同，不是回归的卡死雷。
