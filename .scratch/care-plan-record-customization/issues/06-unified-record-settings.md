# 06 — 统一记录设置与本机拖动排序

**What to build:** 将原先分散的记录相关菜单收敛为一个“记录与快捷设置”二级入口，让用户在同一处管理常用槽位、项目启用、类别顺序和分项目配置。

**Blocked by:** 05 — 四槽常用记录快捷栏.

**Status:** done

- [x] 顶层设置不再平级展示“记录设置 / 自定义项目 / 记录项目”，统一为“记录与快捷设置”
- [x] 二级结构包含常用记录、所有记录项目、分项目设置、护理计划与日历；尚未实现的后续能力不显示虚假可用开关
- [x] 类别支持拖动排序；项目仅能在所属类别内拖动，不得跨类别
- [x] 项目可开启或关闭；关闭保留顺序，再次开启恢复原位
- [x] 具体自定义项目显示在自定义类别；快捷槽位顺序与项目/类别顺序相互独立
- [x] 类别顺序、项目顺序、启用状态和槽位全部是本机偏好，不进入家庭同步模型
- [x] 设置存储和 UI policy 测试覆盖迁移、拖动约束、保序恢复和统一导航
- [x] 常用槽位在窄屏与字体放大时把状态与动作分层，动作可换行且使用“上移 / 下移 / 选择 / 清空”完整文案

## Evidence

- 2026-07-27 Release 收敛：移除重复罗列需求的长说明；常用槽位改为状态行加可换行动作行，避免四个动作与名称挤在同一行。最终候选仍须在 Release 总验收中覆盖小屏与字体放大。
- 2026-07-27 Release 复核纠正“按钮换位即拖动”的旧结论：类别和类别内项目现均提供
  handle-only 长按拖动；释放目标使用当前可见类别标题/项目行的实测窗口中心，项目继续由
  `moveCatalogKeyWithinSection` 保证不能跨类别。状态/开关行与无障碍移动按钮分层，避免
  窄屏或字体放大时把项目名称挤成窄列；若相邻目标尚在视口外，超过 32dp 的边缘拖动
  只移动一位，避免固定行高算法跳项。设备候选证据在 Release 总验收中单独记录。
