# 02 — 灰态确认按钮与具体原因卡

**What to build:** 当记录草稿暂不可保存时，确认按钮保持正常形状并允许用户请求具体解释；点击绝不保存，而是明确指出首个需要修正的字段。

**Blocked by:** None — can start immediately.

**Status:** done

- [x] 校验失败时按钮保持与可保存态相同的尺寸和圆角，使用浅灰填充、灰色描边且无阴影
- [x] 点击灰态按钮不调用持久化，在按钮上方显示非模态具体原因卡
- [x] 原因卡定位、聚焦并高亮第一个无效字段；修正字段后重新校验并恢复正常按钮
- [x] 原因卡持续到字段修改、再次点击灰态按钮或关闭 Composer
- [x] TalkBack 只朗读具体原因，不朗读“暂不可保存，点击查看原因”等固定提示
- [x] 保存中和删除中真正不可点击，不显示原因卡也不重复提交
- [x] 草稿与最小 UI 测试覆盖原因选择、生命周期、辅助功能语义和忙碌态
