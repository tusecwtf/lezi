## Problem Statement

照护者在「记录与快捷设置」里配置常用入口时，只能在四个槽位上**逐个从列表挑选/排序**，无法像整理桌面图标一样，从**任意记录项目**直接拖进四个常用位。所有记录项目的显隐与排序也困在设置弹窗里的列表 + 上移/下移，和日常记录页脱节。

同时：

1. **常用 ≠ 完整目录的拖放关系**：用户心智是「把常用的钉在坞上」，现状却是「在设置里给四个槽填表」。
2. **隐藏与删除语义混在设置开关里**：本机不显示与家庭删除自定义定义容易被同一套「管理」心智混淆。
3. **菜单 hub 过重**：「记录与快捷设置」同时塞布局（常用/所有记录）与非布局（分项目、护理计划与日历），发现成本高。
4. **惯用手镜像坞**与用户自己排的绝对槽序冲突：用户排好的「第 1 个」会因左手/右手被整体挪位，可预期性差。

结果是：想把任意项目（含具体自定义项目）放进四个常用位的成本高，布局调整不像 Android 桌面那样可逆、可拖、可回收。

---

## Solution

在**记录页就地**提供 Android 桌面式的**布局编辑态**，并收窄菜单职责：

1. **长按**记录项目图标（常用坞或更多目录）→ 进入**布局编辑态**；自动展开画布：**上常用四槽 · 中按类所有记录 · 底本机已删除**。
2. **常用记录**是四个本机**快捷方式指针**（不是从目录搬走的项目）；可拖入替换、槽间换位、拖出或 × 清空；同一记录项目不可占多槽（再拖入则与已有槽换位）。
3. **所有记录**保留类别；类内拖排序、类别可排序；不可跨类投放。项目拖入底部**本机已删除**＝本机隐藏（可逆）；从已删除拖回 → 落入所属类**当前可见列表末尾**，且**清空**曾指向它的常用槽（进删除时即清，拖回不自动占槽）。
4. **本机已删除 ≠ 家庭删除自定义定义**；自定义的新增/改名/家庭删除仍在编辑态「自定义」类下的管理入口（含确认流）。
5. 日常「更多」**只点选记账**，无排序/开关/上移下移。
6. 菜单原「记录与快捷设置」改为单页**记录设置**（分项目 + 护理计划/系统日历）；布局不再进菜单。
7. 坞固定为 **`[槽0][槽1][槽2][槽3][更多]`**；**不再**随惯用手镜像坞。惯用手设置保留，仅服务圆盘等表单靠边。

术语以 `CONTEXT.md` 为准。布局偏好继续**本机-only**（ADR-0006）。

## User Stories

1. As a 照护者, I want 长按常用槽或所有记录里的图标进入布局编辑态, so that 我能在记录页就地改布局而不钻设置  
2. As a 照护者, I want 进入编辑态后自动看到常用四槽、分类目录与底部本机已删除, so that 我能从任意项目拖进常用  
3. As a 照护者, I want 编辑态内短按图标不打开 Composer、不写入护理记录, so that 夜喂时不会因整理布局误记账  
4. As a 照护者, I want 点「完成」或系统返回退出编辑态, so that 我能回到干净的日常记录页  
5. As a 照护者, I want 退出后常用坞与更多目录立刻反映新布局, so that 改完就能用  
6. As a 照护者, I want 把「所有记录」里的任一可见记录项目拖到某个常用槽以替换其内容, so that 四个常用可以来自完整目录而不是固定候选  
7. As a 照护者, I want 在常用四槽之间拖动交换位置, so that 我能自己决定左到右的优先级  
8. As a 照护者, I want 同一记录项目不能同时出现在两个常用槽, so that 坞上不会重复占位  
9. As a 照护者, I want 当某项目已在另一常用槽时再拖到目标槽则两槽换位, so that 「交换」手感一致且保持唯一  
10. As a 照护者, I want 从常用槽拖出坞外以清空该槽, so that 我能拿掉快捷方式而不隐藏目录里的项目  
11. As a 照护者, I want 编辑态在常用槽上点 × 清空该槽, so that 不爱拖的时候也能摘掉快捷方式  
12. As a 照护者, I want 清空常用槽后该记录项目仍留在所有记录中, so that 快捷方式模型符合桌面直觉  
13. As a 照护者, I want 空槽被允许（0～4 个有效入口）, so that 我不必硬凑满四个  
14. As a 照护者, I want 非编辑态短按空槽不做任何事, so that 不会弹出旧的槽位选择列表  
15. As a 照护者, I want 非编辑态短按已绑定常用槽仍打开对应 Composer, so that 记账路径不变  
16. As a 照护者, I want 非编辑态点「更多」仍打开所有可见记录项目面板, so that 不在四槽里的类型仍能记  
17. As a 照护者, I want 日常更多面板没有任何排序柄、上移下移或显隐开关, so that 点按只用于记账  
18. As a 照护者, I want 在编辑态把某记录项目拖进底部本机已删除, so that 它不再出现在日常更多与候选中  
19. As a 照护者, I want 项目进入本机已删除时所有指向它的常用槽被立即清空, so that 不会留下失效幽灵槽  
20. As a 照护者, I want 从本机已删除拖回目录后项目出现在所属类别可见列表末尾, so that 恢复位置可预期且不必记旧下标  
21. As a 照护者, I want 从本机已删除拖回后不自动填回常用槽, so that 恢复目录与钉常用是两步明确操作  
22. As a 照护者, I want 允许把全部记录项目都放进本机已删除, so that 布局操作没有人为保底打断（仍可拖回）  
23. As a 照护者, I want 本机已删除只影响本机目录显隐, so that 既有护理记录与家庭数据不被毁掉  
24. As a 照护者, I want 家庭级删除自定义项目定义仍走单独确认, so that 不会和本机已删除长按手势混用  
25. As a 照护者, I want 在编辑态「自定义」类下管理新增/改名/家庭删除, so that 定义管理贴着目录  
26. As a 照护者, I want 自定义类在没有任何可见项目时仍显示分区与管理入口, so that 我能从零创建第一个自定义项目  
27. As a 照护者, I want 其它类别在可见项目为 0 时不显示类标题, so that 编辑画布不被空类占满  
28. As a 照护者, I want 在编辑态拖动类标题调整类别顺序, so that 更多面板的大区顺序仍可编排  
29. As a 照护者, I want 在同一类别内拖动记录项目调整顺序, so that 类内高频项可以靠前  
30. As a 照护者, I want 不能把项目拖到另一类别里, so that 喂养/排泄等分类不会被拖乱  
31. As a 照护者, I want 日常坞从左到右固定为四个槽再「更多」, so that 槽序就是我看到的绝对左右序  
32. As a 照护者, I want 常用坞不再因左手/右手设置整体镜像, so that 我排的顺序不会被系统改位  
33. As a 照护者, I want 显示设置里仍能选择惯用手以影响时间圆盘等表单靠边, so that 单手录入其它控件不受本次布局改动误伤  
34. As a 照护者, I want 菜单里用「记录设置」替代「记录与快捷设置」, so that 名称不再暗示在菜单里改快捷布局  
35. As a 照护者, I want 记录设置单页包含分项目参数与护理计划/系统日历选项, so that 非布局配置仍在原菜单位置一次找齐  
36. As a 照护者, I want 记录设置里不再出现常用槽位或所有记录项目布局入口, so that 布局只在记录页编辑态完成  
37. As a 照护者, I want 系统日历的选目标/披露等仍从记录设置内的配置入口进入, so that 深层配置不丢  
38. As a 照护者, I want 具体自定义项目与内置类型在拖入常用、排序、本机已删除上规则一致, so that 目录身份统一  
39. As a 照护者, I want 已被本机已删除的项目不能作为有效常用绑定保留, so that 坞与目录可见性一致  
40. As a 照护者, I want 布局（槽位、类序、类内序、本机已删除集合）只保存在本机, so that 家庭其它设备的布局不被我打乱（ADR-0006）  
41. As a 照护者, I want warm 与 journal 两套模板共用同一套布局编辑语义, so that 换模板不换规则  
42. As a 照护者, I want 进程被杀后布局偏好仍恢复, so that 我排好的坞和目录不会丢  
43. As a 照护者, I want 首次进入布局编辑态时可看到简短说明（一次性即可）, so that 我知道拖到常用是替换、拖到底是隐藏  
44. As a 开发者 agent, I want 布局规则集中在可单测的本机布局策略中, so that 不必靠 Compose 拖拽测产品不变量  
45. As a 照护者, I want 时间轴上仍能打开已隐藏类型的历史护理记录进行编辑, so that 本机已删除不影响既成事实  
46. As a 照护者, I want 搜索等其它入口的既有行为不因本机已删除而破坏历史查阅, so that 隐藏只约束「新建入口目录」  
47. As a 照护者, I want 编辑态下仍能区分「移除常用快捷方式」与「丢进本机已删除」, so that 两种桌面动作不会混成一种  
48. As a 照护者, I want 从所有记录拖到已占用槽时覆盖该槽原快捷方式（原项目回目录仍在）, so that 替换不会误删目录项  
49. As a 照护者, I want 退出编辑态时若目录全空也不被强制拦截, so that 可逆布局不被「至少留一个」打断  
50. As a 照护者, I want 不再在设置弹窗里用上移/下移按钮管理布局, so that 只保留桌面式拖动一条路径

## Implementation Decisions

### 术语与不变量

- **记录项目**：可新建护理记录/护理计划的具体入口（内置或具体自定义），稳定 catalog key，归属一记录类别。
- **常用记录**：固定四槽快捷方式指针；空槽允许；四槽内 catalog key **唯一**；摘快捷方式 ≠ 进本机已删除。
- **本机已删除**：本机目录回收站；对应并升级现有 `hiddenItems` 语义（产品名用本机已删除）；**不**家庭 tombstone 自定义定义。
- **布局编辑态**：记录页临时模式；短按不记账；完成/返回退出。
- **记录设置**：菜单原位单页；仅分项目 + 护理计划/系统日历。

### 主缝：本机布局策略（唯一核心规则源）

所有下列行为必须由**纯函数/策略层**表达，Compose 只发意图（拖入槽、槽间交换、清槽、进已删除、从已删除恢复、类内移动、类移动）：

| 操作 | 结果 |
|------|------|
| 指派记录项目 → 槽 i | 槽 i = 该 key；若 key 已在槽 j，则 i 与 j **换位**（唯一性） |
| 槽 a ↔ 槽 b | 两槽内容交换；长度仍为 4 |
| 清空槽 i | 槽 i = 空；目录不变 |
| 项目 → 本机已删除 | key 加入本机已删除集合；**所有**等于该 key 的常用槽改为空；不改写家庭定义 |
| 本机已删除 → 恢复 | key 移出已删除；插入所属类别**当前可见顺序的末尾**（不恢复隐藏前精确下标）；不自动写入常用槽 |
| 类内移动 | 仅同类 catalog keys 重排；跨类为 no-op |
| 类别排序 | 仅类别序变化；项目不跨类 |

持久化继续使用本机 Settings 侧字段族（槽列表、item order、category order、hidden/已删除集合）；**不**引入家庭同步字段。是否重命名存储键为实现细节，对外语义以本机已删除为准。

**与旧行为差异（实现时改测试口径）：**

1. 恢复位置：旧「隐藏不改 order → 恢复原相对位」→ 新「恢复到类可见末尾」。
2. 隐藏占槽：旧「resolve 时空白但存储可仍引用」→ 新「进入已删除时**清空存储槽引用**」。
3. 坞序：旧 `oneHandQuickDockOrder(hand)` 左右镜像 → 新固定 `[四槽…][更多]`；惯用手不再参与坞布局函数。

### 薄缝：坞/空槽动作映射

非编辑态：

- Bound 槽 → 打开对应 Composer（或既有类型专属动作，如睡眠状态机）
- More → 打开更多
- Empty → **无操作**（删除 `OpenSlotSettings` 一类路径）

编辑态：短按不派发记账动作；布局手势走主缝。

### 薄缝：菜单信息架构

- 移除「记录与快捷设置」四入口 hub（常用 / 所有记录 / 分项目 / 护理计划与日历）。
- 原菜单位置：**记录设置**单页 = 原分项目内容 + 原护理计划与日历内容（系统日历配置仍可二级弹出）。
- 显示设置：保留惯用手；文案不再声称「常用入口靠近拇指侧」若该句仅描述坞镜像；圆盘/表单靠边行为保持。

### UI / 交互

- 进入编辑态：长按任一记录项目图标（坞或更多内）。
- 进入后自动展开布局画布（不必先手动打开更多）。
- 替换/排序：**仅拖放**，不提供点选替换列表或槽位 FilterChip 选择器。
- 编辑态常用槽提供 × 清空；拖出坞外亦清空。
- 空类（可见项目为 0）：**不显示**类头；**自定义类例外**（始终显示 + 管理/新增）。
- 日常更多：按本机类序与类内序展示**非**本机已删除项目；纯点选。
- 两套 visual style 共用语义。
- 可做一次性编辑引导；非必须永久「编辑布局」菜单项。

### 模块边界（逻辑，非绑路径）

- **记录页 / 快捷坞**：编辑态宿主、手势、日常动作映射。
- **本机布局策略**：槽与目录/已删除不变量（主缝）。
- **目录序工具**：类序与类内序（已有能力上对齐新恢复规则）。
- **设置菜单**：记录设置单页；删除布局相关 dialog 入口。
- **自定义项目管理**：仍本机 UI + 既有 domain 所有权/同步；仅入口挪到编辑态自定义类。
- **惯用手**：保留 DataStore/设置；断开与坞顺序的耦合。

### 明确不改

- 家庭同步协议、自定义定义共享规则（ADR-0006）、护理计划/系统日历投影算法本身。
- 桌面小组件快捷类型是否与常用四槽联动（保持独立，除非另开 spec）。
- 无障碍的完整替代输入方案（可后续加；本版以拖放为主）。

## Testing Decisions

### 何为好测试

- 只断言**外部行为与不变量**（槽列表、已删除集合、类内可见序、动作枚举），不断言 Compose 节点结构或像素拖距。
- 规则变更时，旧测试若编码了「恢复保序」「隐藏留槽引用」「左右手坞镜像」必须改写或删除，避免锁死被取代行为。
- 优先 JVM 单测主缝；UI 烟测可选、非规则源。

### 测什么（按缝）

**主缝 — 本机布局策略**

- 指派到空槽 / 替换已占槽  
- 唯一性：已在槽 j 的 key 指派到槽 i → 换位  
- 槽间 swap 长度恒为 4  
- 清空槽不影响目录与已删除  
- 进本机已删除 → hidden 集合含 key 且所有匹配槽变空  
- 恢复 → 不在已删除；出现在该类可见序末尾；常用槽不自动恢复  
- 允许全部进入已删除  
- 类内移动不拉入外类 key；跨类 no-op  
- 类别排序边界  

**薄缝 — 坞动作**

- Empty 非编辑态 action = none（非 OpenSlotSettings）  
- Bound / More 既有 action 保持  
- 固定坞序：四槽后接 More；与 preferredHand 无关  

**薄缝 — 菜单**

- 记录设置目的地集合 = 分项目 + 计划日历（无常用/所有记录布局）  
- 或等价的导航描述纯函数  

### 先验（prior art）

- `QuickRecordSlotsTest`：槽 resolve、swap、候选、（将改写的）hand 坞序与 empty action  
- `RecordAndShortcutSettingsTest` / `RecordCatalogOrderTest`：类内移动、跨类 no-op、类别序、（将改写的）hide/restore 保序  
- 设置 hub 目的地列表式单测（若已有 `recordShortcutHubDestinations` 一类）  

### 回归信号

- 新测应在「仅列表挑选四槽、隐藏不请槽、恢复保序、左右手镜像坞、空槽打开设置」的旧实现上失败，并在本 spec 实现后通过。
