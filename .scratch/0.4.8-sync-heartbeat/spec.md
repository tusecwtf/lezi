# 0.4.8 前台心跳同步

> 可行性研究、对抗审查判定与兼容矩阵见同目录 `research.md`。

## Problem Statement

两台家庭成员设备同时开着乐记时，一台记录了喂养或换尿布，另一台的时间轴**不会有任何变化**——
今天所有同步触发都是事件驱动（回前台、网络恢复、本地写、下拉刷新），前台期间没有任何机制
检查「服务器上有没有别人的新事实」。家人看到的就是「同步慢了 / 坏了」，实际是根本没有轮询。
而 docs 又明文禁止后台轮询、FCM 和常驻前台服务，所以缺口只能在前台期内以用户无感知的方式补上。

## Solution

前台心跳：app 在前台期间按自适应节奏（30s 基线，无变化退避至 120s）向服务端发一个
~100 字节的只读探针，拿到三个信号——安装世代（generation）、家庭事实水位（head_rev）、
目录摘要（directory_generation）。信号与本机会话快照不一致（含灾难恢复后的水位回退）就
踢一脚**既有**同步循环（一次前台轮：拉+推）；一致就静默等待下一拍。

- 用户无新增任何 UI、开关、提示；主时间轴/状态行对探测失败零感知（可用性照实翻转，
  但只在网络设置页可见）。
- 心跳与可用性**统一为一个模型**：同一次探针同时喂「变化信号」和「活性」——成功复健
  并刷新最近健康时间，失败按既有分类降级、降级期按既有 30s/120s/600s 梯子自动重探，
  顺带修掉今天「降级后只有打开设置页才会重新探活」的存量缺口。
- 后台零探测（取消式生命周期，对齐「进入后台停止探测和同步」合同）。
- 服务端不新增每设备状态；心跳的唯一客户端动作是经跨拍熔断缝踢既有 conflated
  前台循环（`ForegroundRoundFuse`，见触发矩阵），conflation、零进度熔断、120s 轮上限、
  幂等应用全部复用既有机制。
- 老 APK × 新服务端零感知；新 APK × 老服务端优雅停用（现状行为）。

## User Stories

1. 作为同时开着 app 的家庭成员，我想在对端记录喂养/换尿布后，最迟约一个心跳周期加一轮同步
   内本机时间轴自动出现该记录，以便不需要下拉刷新或切后台再回来。
2. 作为夜间喂奶时让 app 被动亮屏的父母，我想让心跳在无变化时自动退避到 120s 并带 ±20% 抖动，
   以便手机无线电能回低功耗态、电量无感知回归。
3. 作为家庭成员，我想让心跳完全静默——没有新开关、新提示，失败不弹错不降级状态行，
   以便「无感知」是字面意义。
4. 作为把 app 退到后台的成员，我想让探针立即**取消**（而非跳过），以便遵守
   「进入后台停止探测和同步」的既有合同、不耗电不耗流量。
5. 作为服务器不可达时的成员，我想让本地写照常落库、主时间轴与账户状态行不受心跳探测
   影响，以便被动使用时完全无感知（可用性照实降级，仅网络设置页可见）。
6. 作为灾难恢复后的家庭成员，我想让服务端水位**回退**也被识别为变化（判 `!=` 而非 `>`），
   以便设备自动进入全量重对账而不是静默卡死到有人手动下拉。
7. 作为家庭管理员，我想让家庭改名、成员/设备变更在安静期也最迟一个周期内传播到前台设备，
   以便目录信息不依赖某人碰巧触发同步。
8. 作为使用旧服务端（或 NAS 回滚到旧容器）的用户，我想让新 APK 优雅停用心跳、
   行为与现状完全一致，以便升级零风险。
9. 作为重新登录/被移除后重加的成员，我想让心跳循环随会话状态（未加入/需重登）立即取消，
   以便不向已失效端点空探。
10. 作为乐记维护者，我想让能力广播只经 setup-status 的增量 capabilities 下发，
    以便不破坏握手 capabilities 的冻结精确键集匹配（老客户端会因此握手失败）。
11. 作为乐记维护者，我想让心跳的唯一动作是踢既有 conflated 同步信号循环，
    以便不新增状态机出口——熔断、轮上限、幂等应用、前台门全部复用。
12. 作为乐记维护者，我想让探针复用既有 Probe 预算类（单次尝试、秒级超时）且不持前台
    keep-alive，以便 H15 预算合同与「每轮后释放」契约不变。
13. 作为乐记维护者，我想让探针收到的 401 终态码走既有设备移除/家庭删除异常映射、
    TOFU 证书变化照常浮现为 TrustChanged，以便生命周期与安全信号不被「静默」吞掉。
14. 作为乐记维护者，我想让心跳成为可用性模型的常驻喂食者——成功即复健并刷新最近健康
    时间，失败按既有传输失败分类降级且无新迟滞——以便一个模型一种真相，降级后恢复探测
    自动化，不再依赖有人打开设置页。
15. 作为乐记维护者，我想让服务端探针 handler 不驻留家庭锁、日志走 DEBUG、配专属限流
    scope，以便探针不影响提交延迟、日志量与滥用面都受控。
16. 作为乐记维护者，我想让 `wait` 查询参数在 v1 占位但被服务端忽略，以便未来升级
    long-poll 不需要破坏 wire。
17. 作为乐记维护者，我想让「成员最近同步 ≈ 最后探针」的语义变化写进 wire 文档注记，
    以便产品语义有据可查（设备前台在线时显示「刚刚」判定为诚实语义）。
18. 作为乐记维护者，我想让本地写后约 2 个回声前台轮（把自己的实体幂等拉回，顺带收敛
    对端与 census）被明示接受并修订 wire §13 说明，以便这项成本不被误当免费。
19. 作为乐记维护者，我想让家庭改名补 bump 家庭事实水位（顺带修复与心跳无关的存量
    传播盲区），以便心跳信号覆盖全部家庭可见变化。
20. 作为乐记维护者，我想让客户端断言集中在既有两个缝隙——端口信号循环级（生命周期、
    节拍、抑制、静默）与纯判定函数（信号×会话快照→动作），以便缝隙数量不膨胀。
21. 作为乐记维护者，我想让心跳触发轮计入零进度续跑熔断，以便任何探针 bug 引发的
    空轮风暴都被既有保险丝封顶。
22. 作为运维发布者，我想让心跳随 VPS/NAS 的同版本 APK+服务端配对一起发布与回滚，
    以便不出现交叉态。
23. 作为打开网络设置页的成员，我想让已加入设备的手动刷新只发一次认证心跳并拿到家族级
    真相（水位/目录摘要/活性），以便设置页看到的与同步引擎看到的同源；未加入场景仍可
    用匿名探测。
24. 作为乐记维护者，我想让降级期心跳节奏切换为既有 30s/120s/600s 重试梯，以便恢复探测
    复用既有机制、不新增定时器族。

## Implementation Decisions

- **模块**：`sync`（availability 探针引擎统一、RealSyncPort 心跳协程、信号比对判定）；
  `tools/lezi-sync`（新探针路由、改名 bump 水位、限流 scope、DEBUG 日志）；`docs/prd`
  （wire §1 增量能力语义、§7.1 认证探针可携带家庭元数据、§13 回声说明、tech.md §3
  租约措辞对齐现实）。不动 `app`、`domain`、数据库 schema、UI。
- **API 契约**：新增认证路由 `GET /v1/sync/heartbeat`（Bearer 设备 token），响应为闭合
  三键 `{generation, head_rev, directory_generation}`；可选 `wait` 参数 v1 一律按 0 忽略。
  能力 `sync_heartbeat_v1` **只**出现在 setup-status 的增量 capabilities。
- **触发矩阵**（客户端唯一动作 = 经跨拍熔断缝触发一次前台轮）：`head_rev != 本机 cursor`
  （含 `<`）、`directory_generation` 不等、`generation` 不等——三者任一即踢循环；
  401 终态码走既有异常映射；全等则无动作。**跨拍熔断（review P2-6 修复）**：同一
  会话/端点 × 同一观测三键信号在零进度预算（≤3 静默续跑）耗尽后熔断——后续同信号
  拍照常探针、照常喂可用性，但绝不再开数据轮；三键任一不同（水位回退也算）、真实
  回前台/本地写/下拉/网络恢复、成功或耐久进度均解除熔断并重置计数；会话/端点/成员
  身份切换整体作废旧熔断；心跳的踢与内部续跑不经 `requestSync` 真实触发缝，不得被
  当成回前台清熔断。
- **客户端循环**：前台 + 已加入 + 端点已 TOFU 固定时启动；后台取消（非跳过）；观察会话流，
  未加入/需重登即取消；`Syncing` 状态跳过当拍不累积。节奏 30s 基线 → 无变化按 ±20% 抖动
  退避至 120s；本地写完成、探到变化、回前台重置基线；回前台首拍 +8s 防抖。
- **失败/活性语义（统一模型）**：心跳是可用性状态的常驻喂食者——成功即复健 Available
  并刷新最近健康时间，失败按既有传输失败分类降级（单次即降级、无新迟滞，与既有喂食者
  一致），降级期节奏切换为既有 30s/120s/600s 重试梯；不写失败种类、不进同步失败 UI
  （主界面不采集可用性，仅网络设置页可见）。TOFU 证书变化照常浮现。探针永不持前台
  keep-alive、永不把状态行翻成 Syncing。老服务端（无能力或 404）视为永久停用，不走
  同步失败路径。
- **探针形态统一**：已加入 + 前台以认证心跳为活性与变化的唯一真相源；网络设置页手动
  刷新在已加入态改发单次心跳，匿名 /health+/ready+setup 探测保留给未加入/无 token 场景。
- **服务端**：family 锁内单行读水位 + 目录摘要重算，锁释放后再构造响应；DEBUG 级日志；
  专属限流 scope；`authenticate` 既有 60s last_used_at 去抖不变。
- **明确拒绝（v1）**：long-poll、SSE、WebSocket、FCM、后台同步、服务端每设备 ack 状态、
  只读认证变体、任何新 UI/设置项。
- **版本落点**：并入 0.4.8 发布（2026-09-05 用户定稿，推翻首版「独立 0.4.9」）——与
  auto-near-neighbor、generation-hot-resume、ui-copy-hardening 同版本上线；本树工单独立管理。

## Testing Decisions

- 好测试只断言外部行为：用假时钟/假后端观察「探针节拍与被触发的同步请求」，断言可观察
  输出，不测协程内部结构。
- 客户端（`sync` 模块，三缝隙布局，先例：availability 探活测试、0.4.8 前台续跑/零进度
  熔断测试、live census 对账测试）：
  - 探针引擎级（统一模型核心，假时钟断言探针时刻与状态迁移）：状态机迁移（成功复健/
    失败降级/无迟滞）、节奏切换（健康退避 ↔ 降级梯子）、三键×会话快照判定（全等无动作、
    水位前移/回退触发、目录摘要不等触发、世代不等触发）。
  - RealSyncPort 集成级：变化信号→踢 conflated 循环、前台启动/后台取消后零探针、回前台
    +8s 防抖、`Syncing` 抑制、会话失效取消、失败不进同步失败 UI（状态行/失败种类断言
    不变）、401 终态走既有映射、旧服务端 404 永久停用；跨拍熔断回归必须跨熔断后数拍——
    同信号后 handshake/pull 不增长而心跳照常且 availability 照常刷新，变化信号（含水位
    回退）恢复一轮，真实回前台/本地写恢复并重置计数，身份切换对同信号不串门（全部用
    既有假时钟+录制后端，不得只依赖测试布尔函数）。
- 服务端（`tools/lezi-sync` 路由测试，先例：pull/census/restore 测试）：认证必需、
  响应闭合三键、探针不阻塞并发提交（锁纪律）、改名后水位变化、限流生效。
- 联调：按 research.md §9 验收标准做最小前后端 smoke（前台自动出现对端记录、后台零流量、
  恢复场景自动全量重对账）。

## Out of Scope

- long-poll / SSE / WebSocket 通道本体（仅留 `wait` 参数占位）。
- FCM、任何形式的后台同步、常驻前台服务。
- 服务端每设备 ack 状态、只读认证变体。
- 任何新 UI、设置项、状态行变化。
- 其余三条 0.4.8 流（auto-near-neighbor、generation-hot-resume、ui-copy-hardening）的实现与
  收口（各自工单树负责）。
- 目录摘要的服务端缓存优化。
