# Spec: 0.2.4 后跟进 — 止血 · 拆骨 · 契约瘦身

Status: complete
Feature: post-0.2.4-followup
Product: 乐记 (`com.lezi.babylog`)
Source: code-review + 四路对抗审查 + grill 决策锁定 · `/to-spec` 2026-07-26
Related: 0.2.4 harden 提交（家庭成员投影、pull 分页、计时幂等、导出、家网 hardening）

---

## Problem Statement

0.2.4 把大量「硬化」一次装进同一发布：行为与自动化测试大体变好了，但照护者与维护者仍面对三层问题：

1. **正确性尖角仍在。** 已加入家庭时「清除本机记录」的承诺是「本机清空、家庭服务器仍保留、下次同步可能拉回」；实现上若清除屏障中途失败，可能出现本机已删、Outbox 仍待推送，从而把「已清除」的历史重新推上家庭服务器。计时完成用稳定幂等键时，若撞上已软删记录会假成功。分页 pull 在故障/恶意服务器下缺少硬上限，且「触顶却无 `has_more`」时可能静默当成功。
2. **可维护性明显回退。** 账户/家庭屏、计时屏、同步端口实现、家用 NAS 服务端仍是超大模块；新能力继续内联堆叠。网络保存成功曾依赖中文文案子串判断；家庭 UI 状态是大量布尔与回调续体，而不是清晰对话框模型。
3. **契约与产品概念变胖。** `SyncPort` 可选参数变多，加入家庭在引导与账户两处重复实现；家网 endpoint 多字段真源（host/port/scheme/baseUrl）与 PRD 脱节；成员列表等新产品面与「硬化」叙事绑在同一大提交里，后续难 bisect、难 revert。

照护者不需要知道模块行数，但需要：**清除不会悄悄复活、计时完成可信、同步不会假成功、家庭与加入流程可理解**。维护者需要：**能按阶段改、能审、能回滚**。

---

## Solution

按 **三阶段路线图** 交付，禁止再开「资源 + 协议 + UI」式 mega-commit。每阶段一主题、可独立合并与回归。

### 阶段总览

| 阶段 | 名称 | 目标 | 行为变化 |
|------|------|------|----------|
| **P1** | 发版止血 | 堵住数据损坏与假成功；文案/威胁模型诚实；最薄提取 | **允许**修正错误行为与文案 |
| **P2** | 结构拆骨 | 拆家庭 / 计时 / 同步客户端 / 服务端薄模块；行为冻结 | **原则上零**产品行为变化 |
| **P3** | 契约瘦身 | Join 命令对象、bootstrap 非空、members 软解析、endpoint 真源收敛、引导与家庭共用加入、PRD 对齐 | **允许**兼容向 API/UX 收敛 |

### 用户可感知结果（跨阶段）

- **清除本机记录（已加入家庭）**：明确是本机操作；家庭服务器历史保留；下次在家网同步时**可能重新下载**；失败时不会把已删记录再推回服务器；可重试清理屏障。
- **母乳计时完成**：崩溃重放对未删除记录仍幂等；用户已删掉的那次完成**不会**假成功。
- **同步**：分页有上限；异常分页协议 fail-closed，不装成「已同步完」。
- **家网**：health 探测不再被重定向/超大 body 误导；产品说明默认家网 HTTP 的威胁边界。
- **维护体验（间接）**：家庭/计时/同步可按文件边界改；加入家庭一条路径；配置真源清晰。

## User Stories

### 清除与本地数据（P1 为主）

1. As a 照护者, I want 清除本机记录时看懂「只清本机、家庭服务器还在」, so that 我不会以为全家历史被永久抹掉
2. As a 照护者, I want 已加入家庭时清除后知道下次同步可能拉回服务器记录, so that 我不会以为「删了就不会再出现」
3. As a 照护者, I want 清除失败时得到诚实说明（本机可能已部分清理）, so that 我知道要不要重试而不是以为什么都没发生
4. As a 照护者, I want 清除过程中途失败后已删记录不会再被推上家庭服务器, so that 我不会「删了又传回去」
5. As a 照护者, I want 在清除失败后能重试完成清理屏障, so that 设备能回到一致的可同步状态
6. As a 照护者, I want 清除成功后本机提醒/闹钟不再为已删日程响起, so that 记录没了闹钟也不该还在
7. As a 照护者, I want 清除全部本地数据时同样遵守屏障与失败语义, so that 换机/重置路径与清记录一样可靠
8. As a 照护者, I want 未加入家庭时清除仍只影响本机且语义简单, so that 单机用户不被家庭文案吓到

### 母乳计时（P1 为主，P2 搬家）

9. As a 照护者, I want 完成喂养写入后即使进程被杀再打开也不会双记, so that 幂等完成可信
10. As a 照护者, I want 若我已删除那次哺乳记录，崩溃重放不会假装又记成功, so that 删除意图被尊重
11. As a 照护者, I want 计时界面在完成失败时仍能看到计时数据（软删冲突时）, so that 我可以改记或重试而不是数据凭空消失
12. As a 照护者, I want 前台计时服务与界面状态一致, so that 通知上的左右时长不离谱

### 同步与分页（P1 为主）

13. As a 照护者, I want 家庭历史很多时同步仍能分页拉完（正常服务器）, so that 大库也能对齐
14. As a 照护者, I want 同步遇到异常分页（页数爆炸或触顶无结束标记）时失败并提示, so that 我不会以为已经同步完其实丢了后面
15. As a 照护者, I want 家网 health 不被恶意重定向或超大响应骗过, so that 门闩不会在错误网络上放行
16. As a 管理员, I want 建家/加入在错误口令或坏请求时不无故耗尽限流（既有行为保持）, so that 手滑重试仍可用

### 家庭账户与加入（P2/P3）

17. As a 管理员, I want 用初始化口令建家时口令不能为空提交, so that 不会对着未配置密钥的服务器空撞
18. As a 成员, I want 扫码/填码加入时服务器地址与 Wi‑Fi 预填来自同一套规则, so that 引导和账户页不会各写各的
19. As a 照护者, I want 加入家庭时展示名不会把「我（本机）」传到别人手机上, so that 隐私占位不会泄漏
20. As a 照护者, I want 成员列表只看到安全投影（名/角色/是否本机）, so that 令牌与设备标识不出现在 UI
21. As a 照护者, I want 不在家网时成员列表失败有可理解状态, so that 我知道要连家庭 Wi‑Fi 再刷新
22. As a 照护者, I want 保存家庭网络配置的成功/失败不依赖某句固定文案是否出现在提示里, so that 改文案不会悄悄弄坏流程
23. As a 照护者, I want 家庭页对话框（加入/创建/离开/删除/网络）状态互斥清晰, so that 不会叠一堆半开弹层

### 配置与契约（P3）

24. As a 照护者, I want 改 host/port/协议方案后实际连接地址可预期, so that 不会「界面一个地址、同步另一个」
25. As a 管理员, I want HTTPS 反代场景下 scheme 作为一等配置被保存, so that 重装客户端后仍连对
26. As a 成员, I want 旧版或残缺成员响应尽量软降级而不是整页崩溃, so that 家庭 tab 更耐造
27. As a 部署者, I want README/PRD 写清默认家网 HTTP 与婴儿数据敏感性, so that 我不会把服务裸奔公网还以为安全

### 维护者 / Agent（P2/P3 + 过程）

28. As a 维护者, I want 家庭功能按 ViewModel / 策略 / 路由 / 网络表单 / 对话框拆开, so that 改一处不必读两千行
29. As a 维护者, I want 计时状态、ViewModel、前台服务、UI 分文件, so that Service 与 Compose 不再捆死
30. As a 维护者, I want HTTP 同步后端与编排端口分离, so that 传输 hardening 与副本引擎可独立测
31. As a 维护者, I want lezi-sync 的限流、就绪、成员投影成模块, so that 服务端改动可定位
32. As a 维护者, I want 一 PR 一主题且契约变更带文档与测试, so that 0.2.4 式大包不再重演
33. As a 维护者, I want 禁止再往已超大的生产文件直接堆功能（先拆再改）, so that 行数债务有门禁
34. As a 开发者 agent, I want 行为测在稳定接缝（CareLog / SyncPort / 配置 / 服务端 API）, so that 不靠脆弱全 UI 录制
35. As a 维护者, I want P1 修对后 P2 只搬家不改语义, so that 拆分 diff 可审
36. As a 维护者, I want P3 改 SyncPort 时 PRD 同步更新, so that 文档不再描述已删除的可选参数形状

## Implementation Decisions

### 总纪律

1. **三阶段串行目标，可并行的仅限 P2 内 Family 与 Timer 两个独立 PR（仍按 Family → Timer → RealSyncPort → Rust 的优先序交付与合并）。**
2. **一 PR 一主题**；禁止「资源 + 协议 + 多 feature UI」捆提交。
3. **契约 / wire 变更**必须同 PR 更新 PRD（data-model / sync-home-lan 等）与测试。
4. **生产源文件门禁**：禁止向已超过约 800 行的模块继续堆新功能；先拆再改。拆分完成后家庭相关生产文件目标约 ≤500 行（硬顶 800）。
5. **P1 结构权限 = 最薄拆分**：只允许为修 bug 服务的 Result/纯函数/小类型提取；**禁止** P1 整体拆家庭上帝屏。
6. **P2 行为冻结**：产品可观察行为与 P1 结束后一致；仅允许可见性/`internal`、文件搬家、等价重构。
7. **明确永不纳入本路线图**：TLS/mTLS 默认、leave 吊销设备全部历史 token、BSSID 门闩、清除时向家庭写全量 tombstone 的「全家永久删除」协议。

### P1 — 发版止血

#### 产品语义：清除

8. **已加入家庭时清除 = 仅本机。** 家庭服务器数据保留。文案必须持续诚实说明「下次家庭同步可能重新下载」（现有二次确认文案方向正确，按需补失败/重试句，不改成「永久删除」）。
9. **不**在 P1 做「清除后自动暂停同步直到确认」或「自动 leave」。
10. **不**在 P1 做服务器侧 tombstone 清历史。

#### 清除失败策略（成功后置 + 补偿）

11. **仅当清除屏障全部完成**才对 UI 返回成功。
12. 若领域层记录/日程删除已提交而后续步骤失败：
    - 仍须取消已无记录支撑的提醒；
    - 清除或耗尽相关 Outbox（或等价：**禁止**再 push 已删记录类型）；
    - UI 失败文案说明本机可能已部分清理、家庭服务器仍保留、请重试清理；
    - 提供**重试屏障**路径（不承诺恢复本机已删内容）。
13. 领域清除与同步端口清除屏障的编排保持「先领域提交、再同步侧收尾」的现有结构时，必须补上 **提交后失败** 的补偿与测试（今日仅覆盖「领域提交前失败」不足）。

#### 计时完成幂等

14. 对**未删除**的同 `clientUuid` 哺乳记录：保持 first-write-wins 幂等。
15. 若同键记录 **已软删**：失败关闭——不得返回已删 id 当成功；计时完成路径不得因此清空会话并假装完成。
16. 冲突时产品文案简短可懂（重试/改记），不暴露内部 uuid。

#### 分页与同步安全

17. 客户端多页 pull：**硬上限页数**（具名常量；默认按约 500 页量级，实现时以「正常家用库远低於此、异常才触顶」为准写入常量注释）。超限 → sync **失败** + 可重试文案。
18. 当本页实体数达到服务端 page 容量语义且响应 **缺少** `has_more`：**fail-closed**（失败），不得默认 `hasMore=false` 当成功。
19. 正常新服务器带 `has_more`、旧服务器单页完整无字段：保持兼容（单页且未触顶则成功）。

#### Health 探测

20. 家网 health 探测与同步 HTTP 客户端对齐：**不跟随重定向** + **响应体大小上限**（错误/成功分档可与同步侧同量级策略）。

#### 网络保存成功判定

21. 禁止用中文提示串 `contains("已保存")` 等文案子串驱动控制流。改为 **显式 Result / sealed 结果** 从 ViewModel/用例回到 UI。

#### 文档与威胁模型（最小）

22. P1 文档只补本阶段已动行为：清除语义、分页上限与 fail-closed、health  hardening 摘要。
23. 用简短段落写清：**默认家网 HTTP，数据在家庭局域网上可被同网设备读取；非 TLS 远程/公网场景不在支持范围。**
24. 完整 SyncPort 表、scheme 真源长文、members 契约细表 → **P3**。

#### P1 明确后移

25. 成员列表静默刷新自愈 → P2。
26. create 与 join 的 display_name 校验对齐 → P3。
27. 「我（本机）」跨端单一常量 → P2（随拆分落地）。

### P2 — 结构拆骨

#### 顺序

28. **Family → Timer → RealSyncPort（客户端）→ lezi-sync 薄模块。**
29. Family 与 Timer 可以两个 PR 并行开发，但 **不要** 与 RealSyncPort 大拆同一审阅批次混在一起。

#### 家庭功能

30. 目标形态（逻辑模块，非强制文件名）：
    - 家庭 ViewModel
    - 家庭 UI 策略（纯函数：可见性、成员展示名、文案、角色标签等）
    - 家庭路由壳
    - **一份**网络表单（主路径与 sheet 共用）
    - 对话框集（加入/创建/离开/删除/邀请等）
    - 宝宝编辑可独立或并入对话框集
31. 对话框状态收敛为 **sealed 对话框状态**（互斥），替代散落的大量 show* 布尔与「步骤 int」控制流（行为等价）。
32. 删除或真正启用「主界面网络编辑」死路径；不得再保留恒 false 的产品开关却编译死 UI。
33. Kotlin 侧本地展示占位名收敛为**单一常量**；与服务端常量字符串对齐并在 PRD/注释互链一句。

#### 计时

34. 拆为：计时状态（含编解码）· ViewModel · 前台计时 Service · 仅 UI 的路由/屏。
35. 已有完成草稿/完成半屏保持边界；不把完成业务搬回巨型屏文件。

#### 同步客户端

36. P2 **必达**：假后端 · HTTP 后端（含限长读体等传输）· 编排端口 **三分离**；共享的 backend 接口与线模型可同模块。
37. 编排类在拆完后应力求明显小于今日一体文件；若仍显著过大，登记后续「副本应用 / 媒体流水线」拆分为债务，**不阻塞** P2 退出，也 **不** 用 P3 契约工作顶替。

#### lezi-sync

38. 从巨型库入口抽出薄模块：**限流**、**就绪检查**、**成员列表投影（含 coalesce 与占位名过滤）**。
39. store 的 pull 依赖组逻辑 **慎动**；仅在几乎纯搬家时可选抽出 pull；禁止 P2 借拆分重写 LWW。
40. 成员投影行为与测试保持；占位名与客户端常量对齐。

#### P2 中的小行为允许

41. 成员静默刷新失败后的有限重试/自愈（P1 后移项）可在家庭 ViewModel 归位时做，须可测，避免刷爆家网。

### P3 — 契约瘦身（尽量做满）

#### Join / Create

42. **Join 收成单一命令对象**（邀请材料 + 必填家网配置 + 可选展示名）。Port 内不再用可选参数编码「saved vs QR 优先级」的隐式政策；QR 只做表单预填。
43. 产品路径弱化/删除易脚枪的「只传码、不传配置」别名入口；若保留仅限测试或明确 deprecated。
44. **bootstrap 密钥在 UI 与 Port 层均不可为空/空白** 提交建家；与 Compose 生产必填密钥一致。
45. create 与 join 的 display_name 使用 **同一套 normalize**（含 bidi/控制字符策略与占位名拒绝/剥离）。

#### Members

46. **软解析**：未知 role、缺字段时降级而非硬崩；`is_self` 缺失时安全默认并依赖会话侧高亮策略。
47. **收紧合成 self**：仅在「从未成功联系服务器 / 明确离线占位」等可解释条件注入；避免与服务器空列表语义混淆。

#### Endpoint 真源 = host + port + scheme

48. **持久化权威字段为 host、port、scheme**；`baseUrl` **纯派生**。
49. 迁移旧存储键；读写只经家网配置类型规范化。
50. 邀请载荷与保存网络共用同一配置构造规则。
51. 引导 onboarding 与家庭账户 **共用** Join 用例 + 表单状态，删除双份草稿逻辑。

#### 文档

52. PRD 完整对齐：SyncPort 新形状、list members、pull `has_more` 与 fail-closed、scheme 真源、清除语义、bootstrap。
53. 名称与代码一致（避免文档 `FamilyMemberView` 与实现名长期分叉而不说明）。

### 阶段退出标准（摘要）

| 阶段 | 退出 |
|------|------|
| P1 | 清除提交后失败有补偿测试；软删计时失败关闭有测；分页上限 + 无 has_more 触顶 fail-closed 有测；health 探测 hardening 有测；无文案子串控制流；威胁模型与清除语义文档最小补丁 |
| P2 | 家庭/计时/HTTP·编排分离/服务端薄模块落地；家庭无死网络路径；sealed 对话框；占位名常量；相关模块测试全绿；无故意产品行为回归 |
| P3 | Join 命令化；bootstrap 非空；members 软解析；endpoint 真源 C；onboarding/family 共用加入；create/join 名校验一致；PRD 同步 |

## Testing Decisions

### 好的测试长什么样

- **测外部行为与契约**，不测私有函数布局或 Composable 树形状。
- 优先 **纯函数 / 用例 / 端口** 级，能单元测就不靠模拟器 UI。
- 回归必须锁住：清除屏障、幂等边界、分页失败模式、配置迁移、加入命令输入校验。
- 拆分 PR（P2）以 **既有测试全绿** 为行为冻结证明；不为搬家强行改断言语义。

### 测试接缝（Seams）

优先复用现有最高接缝，少造新抽象。建议接缝如下（实现时保持稳定，供 agent 挂测）：

| # | 接缝 | 覆盖 |
|---|------|------|
| S1 | **CareLog 清除 API** ↔ **SyncPort 本地清除屏障回调** | 清除成功/领域前失败/领域后失败补偿、提醒取消、Outbox 不再推已删记录 |
| S2 | **CareLog.completeNursing（稳定完成键）** | live 幂等；软删失败关闭 |
| S3 | **同步编排的多页 pull 策略**（端口实现级） | 页数上限；触顶无 `has_more` fail-closed；正常 has_more 循环；旧服务器单页 |
| S4 | **家网 health 探测** | 不跟随重定向；超大 body 不误判健康 |
| S5 | **家庭 UI 策略纯函数**（P2 抽出后） | 成员展示名、合成 self 条件、角色文案；无 Compose |

### 模块与 prior art

- **Android 同步：** 既有 `RealSyncPort` 集成向单测、`HttpSyncBackend` 测、清除与 pull 分页相关用例 — 在同一层级扩展「提交后失败」「页数上限」「无 has_more」。
- **领域：** `CareLog` 测试中的 `completeNursing` 幂等 — 增补软删行。
- **家庭文案/策略：** `FamilyErrorCopy` 类纯函数测 — P2 后迁到策略模块继续扩。

### 阶段测试门禁

- **P1：** 新增/更新 S1–S4 相关测试必须红绿驱动；全量相关模块测试通过。

## Out of Scope

- 默认 TLS、证书固定、公网安全远程同步产品化
