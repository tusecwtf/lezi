# 04 — 多权威宝宝时成员孤→权威显式合并

**Parent:** [../spec.md](../spec.md)

**What to build:** 当家庭已有**多个**权威宝宝、成员本机仍有带数据的孤宝宝时，不做昵称自动配对；成员可将**孤宝宝**显式合并进用户点选的**家庭权威宝宝**（预览记录/计划数量，语义对齐现有合并）。合并后源孤宝宝从本机消失、数据挂在目标权威宝宝上，且**不**把源宝宝实体推上家庭服务器。成员**不能**合并两个家庭权威宝宝，也不能用合并绕过档案管理禁令去删权威集合。

**Blocked by:** 01 — 成员不同步宝宝实体；03 — 单权威自动收敛（reconcile 与孤宝宝定义就绪）

**Status:** complete

## Acceptance criteria

- [x] 成员仅允许合并方向：**源 = 本机孤宝宝 → 目标 = 家庭权威宝宝**
- [x] 成员尝试合并两个权威宝宝、或以权威宝宝为源 → 拒绝
- [x] 管理员保持现有任意合法合并能力
- [x] 合并预览仍只展示记录/计划数量等，**不**用昵称裁决身份
- [x] 合并成功：源记录/计划/相关媒体挂到目标；源本机不再活跃；当前宝宝若在源上则落到目标；源 baby **不** push 到 NAS
- [x] 账户宝宝区：仅当存在待收敛孤宝宝时，成员可见「合并到家庭宝宝」类入口；无孤宝宝时成员不暴露会改权威集合的合并/删除
- [x] CareLog 单测覆盖允许/拒绝矩阵与合并后无 baby 出站意图；与 03 的单权威自动路径不互相破坏
- [x] 文案与 02 一致：管理权威档案仍归管理员；本入口只解决「本机旧数据并进哪一个家里的宝宝」
