# 03 — 单权威宝宝时自动收敛本机孤宝宝

**Parent:** [../spec.md](../spec.md)

**What to build:** 成员加入家庭并 pull 到家庭权威宝宝后，对本机「从未出现在家庭服务器上的孤宝宝」做安全收敛。当家庭**恰好有 1 个**活跃权威宝宝时：把孤宝宝下的护理记录、护理计划与相关宝宝向媒体**再绑定**到该权威宝宝，本机软降级/去掉孤宝宝，并把当前宝宝指针落到权威宝宝上——用户看到**只剩一个宝宝**，加入前记的数据仍在。家庭 0 个权威宝宝时：不把本机宝宝当成家庭档案上传（依赖 01），并呈现可理解空态（等待管理员添加宝宝），而不是用孤宝宝冒充家庭权威长期并列。

**Blocked by:** 01 — 成员不同步宝宝实体（客户端 + NAS 护栏）

**Status:** complete

## Acceptance criteria

- [x] 定义并实现成员侧「本机孤宝宝」：本机存在且其 `client_uuid` 不在已 pull 的家庭权威宝宝集合中；且不得作为 baby 上行（01 已保证）
- [x] 成员 + 家庭活跃权威宝宝 **恰好 1 个**：自动将每个孤宝宝上的 Record / CarePlan / 宝宝向媒体再绑定到该权威宝宝；孤宝宝本机不再作为活跃档案展示；`currentBabyId` 落在权威宝宝
- [x] 再绑定产生的 Record/CarePlan 脏写仍可按现规则同步；**仅**孤宝宝实体本身不 push（含降级 tombstone）
- [x] 再绑定后 open sleep 等本机不变量仍正确（对齐既有 merge 后 heal 语义）
- [x] 成员 + 家庭活跃权威宝宝 **0 个**：不上传本机宝宝；UI/列表不把孤宝宝长期呈现为与家庭权威对等的「已接管档案」；有等待管理员的空态或等价提示
- [x] 成员 + 家庭活跃权威宝宝 **≥ 2 个**：本票**不做**昵称猜测自动合并（留给 04）；也不得误删有数据的孤宝宝而不给收敛路径
- [x] 触发点在同步 apply 宝宝集合变化之后的领域 reconcile（CareLog seam），不散落在 Compose
- [x] 端到端可测场景：本机 1 孤宝宝（带记录）+ 家庭 1 权威宝宝（不同 uuid）→ 同步后仅 1 个活跃宝宝且记录挂在权威 uuid 下；出站无 baby
- [x] 管理员设备路径不受影响
