# 02 — 成员禁止管理宝宝档案（CareLog 闸门 + UI）

**Parent:** [../spec.md](../spec.md)

**What to build:** 已加入且角色为**成员**时，宝宝档案管理权上移给家庭管理员：成员不能添加宝宝、不能改昵称/性别/生日/出生体重/头像等家庭档案字段、不能删除家庭宝宝。领域层硬拒绝；账户宝宝区与设置等入口对成员隐藏或禁用管理操作，并给出人话说明「宝宝档案由家庭管理员管理」。未加入与管理员保持完整管理能力；成员仍可在权威宝宝之间切换当前宝宝；本机主题色/排序等不同步偏好仍可改。

**Blocked by:** None — can start immediately（可与 01 并行）

**Status:** complete

## Acceptance criteria

- [x] 成员调用添加宝宝 / 更新家庭档案字段 / 删除宝宝 → 领域层明确权限失败（风格对齐既有计划/自定义项权限异常）
- [x] 管理员与未加入角色：添加、编辑档案、删除（及既有「至少保留一个」约束）行为与现网一致
- [x] 成员仍可 `setCurrentBaby` 在已有宝宝间切换
- [x] 成员可改本机主题色 / 排序（不同步字段）；不得借道同一写路径改动会同步的档案字段
- [x] 账户宝宝区：成员隐藏或禁用「添加 / 编辑档案 / 删除」；管理员入口完整；头像编辑继续仅非成员（与现 `canEditFamilyAvatar` 语义一致并扩展到全档案管理）
- [x] 设置/菜单等其它「添加宝宝」旁路在成员身份下同样不可用
- [x] 权限失败与 UI 拒绝文案用人话（如「宝宝档案由家庭管理员管理」），不暴露 role 枚举/token/uuid
- [x] 成员离开家庭后，本机恢复自主管理宝宝的能力（不永久锁死）
- [x] CareLog / UI 策略单测覆盖成员拒绝、管理员/未加入放行、可见性布尔
