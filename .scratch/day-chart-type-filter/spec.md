## Problem Statement

照护者在记录首页看「一天的节奏」时，时间条（一日时间条）与下方记录明细是拆开的两块信息：

1. **空日也占位**：当日没有任何可上图的节奏类记录时，仍渲染空白三轨卡片，浪费首屏并像「坏了的图」。
2. **点选只停在图内**：现网点色块/圆点只高亮**单段**并弹出 tip，**不会**收窄下方明细，也无法按「只看母乳 / 只看尿」快速扫一天。
3. **类型粒度错位**：物理轨是睡眠 / 喂养 / 护理三轨，用户心智与日汇总却是奶、母乳、睡眠、尿、便；共轨的奶 vs 母乳、尿 vs 便无法单独筛。
4. **图例只读**：图例不能作为同一套筛选入口，和「点图例也能选类型」的预期不符。

结果是：时间条停留在「装饰 + 单段说明」，没有成为「点一类 → 图高亮 + 列表只留该类」的导航。

---

## Solution

在记录首页日视图（**当前选中自然日**）上：

1. **有日图类型数据才显示**整块一日时间条；否则不渲染该卡片（列表空态仍走现有「还没有记录」等逻辑）。
2. 图表**形态保持现网**（warm 横向三轨 / journal 纵向三轨；不强制首版拆五物理轨）。
3. 引入 **日图类型**（五类）与 **日图类型筛选**（临时视图状态）：
   - 点**任一属于该类的色块/圆点**，或点**图例中该类** → 进入筛选态
   - 图：该类全部标记高亮，其它类（含同轨另一类）弱化
   - 列表：记录明细**只显示该类**
   - 图下：类型级提示条（类名 · 条数 · 再点取消）；点提示条可取消
4. **日汇总始终全日口径**，不随筛选变化。
5. **两套界面模板**同一交互语义与同一状态模型。

术语以 `CONTEXT.md` 为准：日图类型、日图类型筛选、护理记录。

## User Stories

1. As a 照护者, I want 当日没有任何日图类型记录时不看到空白时间条, so that 首屏不被空图占位  
2. As a 照护者, I want 当日只有体温/用药/吸奶等非日图类型时也不出时间条, so that 图只代表节奏五类  
3. As a 照护者, I want 当日有奶/母乳/睡眠/尿/便任一记录时看到时间条, so that 我能扫一天节奏  
4. As a 照护者, I want 时间条布局仍是现在的三轨样式, so that 界面不因本次改动大变样  
5. As a 照护者, I want 点某个母乳圆点后只看到母乳明细, so that 我能专注母乳节奏  
6. As a 照护者, I want 点某个配方奶/瓶喂挤出乳标记后只看到「奶」类明细, so that 瓶喂与母乳能分开看  
7. As a 照护者, I want 点睡眠条后只看到睡眠明细, so that 我能回顾睡醒段落  
8. As a 照护者, I want 点尿尿标记后只看到尿相关明细, so that 便便不会混进列表  
9. As a 照护者, I want 点便便标记后只看到便相关明细, so that 尿尿不会混进列表  
10. As a 照护者, I want 尿+便合一记录在筛「尿」或「便」时都出现, so that 合并记录不会丢  
11. As a 照护者, I want 选中某类时图上该类所有标记都高亮, so that 我看到的是整类而不是只亮被点的那一下  
12. As a 照护者, I want 选中母乳时同轨的配方奶标记变淡, so that 共轨两类不会被误读成全亮  
13. As a 照护者, I want 选中尿时同轨的便标记变淡, so that 护理轨内两类可区分  
14. As a 照护者, I want 点图例「母乳」与点母乳色块效果相同, so that 图例也是筛选入口  
15. As a 照护者, I want 图例只显示当日有数据的日图类型, so that 我点不到必然空列表的类  
16. As a 照护者, I want 图例上当前选中类有明确选中态, so that 我知道正在筛什么  
17. As a 照护者, I want 再点已选图例或同类色块时取消筛选, so that 能回到全日明细  
18. As a 照护者, I want 点时间条空白/非命中区时取消筛选, so that 误触后容易退出  
19. As a 照护者, I want 点类型提示条时取消筛选, so that 提示条兼作清除入口  
20. As a 照护者, I want 换日后筛选自动清空, so that 不会把昨天的筛选项带到今天  
21. As a 照护者, I want 筛着某类时该类被删光或同步后不存在则自动取消筛选, so that 不会卡在 0 条死态  
22. As a 照护者, I want 筛选时顶部日汇总数字仍是全日合计, so that 总览不会跟着跳没  
23. As a 照护者, I want 未筛选时明细仍显示体温/用药/吸奶等非日图类型, so that 其它记录不丢  
24. As a 照护者, I want 筛选时明细不显示非当前日图类型, so that 列表真正变短  
25. As a 照护者, I want 吸奶记录不作为日图类型参与出图条件与图例, so that 「奶」只表示喂给宝宝的瓶喂奶  
26. As a 照护者, I want 点时间条不会直接打开编辑, so that 点选用于筛选而不是误进表单  
27. As a 照护者, I want 仍从明细行进入编辑, so that 改记录路径不变  
28. As a 照护者, I want 筛选后明细排序仍遵守设置里的新→旧/旧→新, so that 不另造排序  
29. As a 照护者, I want 类型提示条显示类名与条数, so that 我确认筛到了几条  
30. As a 照护者, I want 提示条提示可再点取消, so that 退出方式可发现  
31. As a 照护者, I want 未结束睡眠仍可作为睡眠日图类型上图与筛选, so that 进行中睡眠不消失  
32. As a 照护者, I want 温暖卡片与紧凑记录簿两套模板行为一致, so that 换模板不会换交互规则  
33. As a 照护者, I want 非今日日期下同样能用日图类型筛选, so that 回看历史日也有同样能力  
34. As a 照护者, I want 下拉刷新后若该类仍在则筛选可保持（数据仍支持时）, so that 刷新不无故打断；若数据已无该类则自动解除（见故事 21）  
35. As a 照护者, I want 时间条上的非日图类型标记（若仍绘制）在筛选态下处于弱化且不可作为选中目标, so that 不会点出无效类型  
36. As a 开发者 agent, I want 日图类型归类与筛选态可用纯函数单测锁定, so that 不必靠截图测 Canvas  
37. As a 照护者, I want 从「奶」切换点「尿」时直接换到尿筛选, so that 切换类型只需一次点击  
38. As a 照护者, I want 空日引导文案仍指向下方快捷入口, so that 无图时仍知道怎么记第一条  
39. As a 照护者, I want 筛选后若列表非空可逐条点开编辑, so that 筛选是导航不是只读死胡同  
40. As a 照护者, I want 日图类型筛选不是持久设置, so that 重启/重进不会莫名其妙还在筛某类

## Implementation Decisions

### 术语与归类

**日图类型**（稳定枚举语义，命名可英文化为 `DayChartCategory` 等）：

| 日图类型 | 命中的护理记录类型 |
|----------|-------------------|
| 奶 | 配方奶、瓶喂挤出乳（`FORMULA`、`PUMPED_FEED`） |
| 母乳 | 母乳（`NURSING`） |
| 睡眠 | 睡眠（`SLEEP`，含未结束） |
| 尿 | 尿尿（`PEE`）；**尿+便**（`BOTH_DIAPER`）也命中 |
| 便 | 便便（`POOP`）；**尿+便**（`BOTH_DIAPER`）也命中 |

- **明确排除**：吸奶（`PUMP_EXPRESS`）、体温、用药、日记、自定义、成长测量等。  
- 一条 `BOTH_DIAPER` 同时属于尿与便（筛选任一类均出现在明细）。  
- 归类是**集合语义**：`categoriesOf(record): Set<DayChartCategory>`；筛选为「记录的集合与选中类相交」。

### 出图条件

- **显示时段** = 当前选中自然日的护理记录集合（与现网日查询一致）。  
- **显示时间条** ⇔ 该日至少一条记录的 `categoriesOf` 非空。  
- 仅有非日图类型 → **不渲染**时间条卡片。  
- 出图后的轨道几何/颜色语言 **保持现网三轨**；不要求首版改为五物理轨。

### 日图类型筛选状态

- 状态形状（语义）：`selected: DayChartCategory?`（null = 未筛选）。  
- **临时、非持久**（不进 DataStore / 设置）。  
- **提升到记录页状态层**（与列表同源），禁止只活在时间条 Composable 内部导致列表无法筛。  
- warm / journal **共享同一状态**；仅绘制不同。

### 交互

| 用户动作 | 结果 |
|----------|------|
| 点中属于类 C 的色块/圆点 | `selected = C`（若已是 C 则 → null） |
| 点图例类 C | 同上 |
| 点空白/未命中 | `selected = null` |
| 点类型提示条 | `selected = null` |
| 点另一类 C2 | `selected = C2` |
| 换日 | `selected = null` |
| 数据变化后 `selected` 已不在「当日有数据的日图类型」集合 | `selected = null` |

- **不可**将非日图类型标记作为选中目标（点中视为未命中或忽略，不进入非法 selected）。  
- **不**因点时间条打开编辑 Composer；编辑仍仅从明细行（及既有入口）。  
- 取消「单段 tip 为主」的语义；改为**类型级提示条**（见下）。

### 高亮与图例

- 选中类 C：所有属于 C 的标记高亮；其它标记弱化（含同物理轨的另一日图类型）。  
- **不是**整条物理轨统一高亮。  
- 图例：  
  - 只列出**当日有数据**的日图类型；  
  - 与色块共享 `selected`；  
  - 选中态可见（描边/强调色等，具体视觉跟设计系统现有选中语言）。  
- 类型提示条（`selected != null` 时）：类名 + 当日该类明细条数 + 再点取消的暗示；点按清除筛选。

### 列表与汇总

- **未筛选**：明细 = 当日全部护理记录（含非日图类型），排序规则不变。  
- **筛选 C**：明细 = `categoriesOf(r)` 含 C 的记录；排序规则不变。  
- **日汇总 / 摘要条**：始终全日聚合，**不**随 `selected` 变。  
- 列表标题是否附带类名：本 spec **不要求**（可选增强，非必须）。

### 与现网绘制的衔接

- 现网 `buildLanes` 等仍可把部分非日图类型画在护理/喂养轨（若保留「按当前显示」）。  
- 出图条件、图例集合、筛选集合、可选中目标 **一律以日图类型表为准**，不得再用「三轨非空」代替。  
- 吸奶：若仍画在喂养轨，**不得**计入出图条件、**不得**进图例、**不得**映射为「奶」筛选；筛选「奶」时吸奶明细不出现，其标记应弱化。  
- `BOTH_DIAPER` 现网可拆成尿/便两个标记：与「两类都命中」一致，保持可点出尿或便。

### 模块边界（逻辑层，不锁文件路径）

- **唯一业务接缝（推荐落地形态）**：纯函数模块「日图类型模型」，对记录页暴露例如：
  - `categoriesOf(type|record)`
  - `shouldShowDayChart(records)`
  - `legendCategories(records)`（有序列表，仅含当日有数据者）
  - `filterRecords(records, selected)`
  - `reconcileSelection(selected, records)`（数据变更后合法化）
  - `toggleSelection(selected, tapped)`（点同类取消、点异类切换）
- **记录页状态**：持有 `selected`，把 reconciler 接到日切换与 records 流。  
- **时间条 UI**：接收 segments + legend + selected + 回调；负责命中测试与绘制，不私藏筛选真源。  
- **无** Room schema / 同步 API / 设置项变更。

### 无障碍（最低）

- 时间条与图例需能表达「可选中以筛选明细」；选中态应对 TalkBack 可读（具体文案实现期对齐现有 `contentDescription` 风格）。不阻塞本 spec 的像素级无障碍专项。

## Testing Decisions

### 什么叫好测试

- 只断言 **对外行为**：给定当日记录列表与选中态/动作，得到是否出图、图例集合、过滤后列表、合法化后的 selected。  
- 不测 Canvas 像素、Compose 命中坐标、主题色值、三轨几何。  
- 不测 Room / 同步。

### 主接缝（唯一）

**日图类型纯模型（Day chart category model）**

从记录页把归类/出图/筛选/选中归约抽成可单测的纯函数（可放在 domain 或 feature 的无 Android 依赖层；优先能被 JVM 单测直接跑）。这是本功能的**唯一交付门禁接缝**。

至少覆盖：

1. 仅非日图类型 → `shouldShowDayChart == false`  
2. 五类各一代表类型 → 出图 true；`categoriesOf` 正确  
3. `FORMULA`/`PUMPED_FEED` → 奶；`NURSING` → 母乳；`PUMP_EXPRESS` → 空集合  
4. `PEE`/`POOP`/`BOTH_DIAPER` 与尿/便集合语义（both 同时命中两类）  
5. `legendCategories` 仅含当日出现的类、无数据类不出现  
6. `filterRecords`：选母乳只留母乳；选尿含 PEE 与 BOTH_DIAPER；未选 = 全量  
7. `toggleSelection`：null→C、C→null、C→C2  
8. `reconcileSelection`：选中类在 records 中消失 → null；仍存在 → 保持  
9. 未结束 `SLEEP` 仍属睡眠日图类型  

### Prior art

- `domain` 侧 `CareAggregation` / `DailySummaryTest`：给定 records 断言聚合对外结果（风格可参考，**不要**把日图类型硬塞进 CareAggregation 除非归类天然属于汇总；日图类型是日视图导航分类，可独立模块）。  
- `feature/log` 草稿单测：纯逻辑、无 Compose。  
- 现网时间条**没有**筛选单测；本 spec **新建**上述接缝，而非扩展脆弱 UI 测试。

### 非主接缝

- 对本功能初始 ready 门禁，Compose UI / 截图 / 真机点轨为可选 smoke；后续固定提交审查
  若以独立整改票重新打开设备交互验收，则该票要求的最终候选 device smoke 是关闭门禁。
- 两套模板视觉一致：人工或截图回归即可，不强制自动化。

## Out of Scope

- **全部 / 白天 / 夜间** 时段芯片与按昼夜裁剪时间条  
- 将三物理轨改成五物理轨的布局重设计（高亮用标记级即可）  
- 点时间条进入编辑 / 新建记录  
- 日汇总、周汇总、Widget、搜索页的筛选或口径变更  
- 把吸奶并入「奶」或单独第六日图类型  
- 筛选状态持久化、跨宝宝记忆  
- 护理计划待履行区与日图类型联动（现网记录页明细以护理记录为主；本 spec 不新增计划筛选）  
- 数据模型、同步协议、导出  
- 重新设计单段时刻 tip 的详情编辑能力

## Further Notes

- Grill 锁定摘要：显示时段=选中日；出图=五类有数据；筛选粒度=五类；奶=配方+瓶喂挤出乳；BOTH_DIAPER 双属；点色块=选类；取消=再点/空白/提示条/换日；高亮=同类标记；图例双入口且仅有数据类；双模板；汇总不随筛；类型级提示条；类被删光自动解除。  
- 与现网差异：段级 tip → 类型筛选；本地 selected → 页级状态；出图条件收紧；喂养轨上的吸奶不再冒充可筛「奶」。  
- **主接缝**：日图类型纯模型（见 Testing Decisions）。若实现时发现必须把接缝上移到 ViewModel 集成测，仍应让纯函数承担归类与过滤真源，ViewModel 仅接线。  
- 可选后续：短 ADR「日图类型五类而非三轨筛选 / 奶不含吸奶」——满足难逆+易惊讶+有权衡时可写 `docs/adr/`。  
- 产品结论落地后，可将出图与筛选行为摘要写回 `docs/prd/ui.md` 一日时间条一行。
