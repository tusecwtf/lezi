# Spec: 区间记录保存前时长预览与确认态

Status: ready-for-agent  
Feature: interval-duration-preview  
Product: 乐记 (`com.lezi.babylog`)  
Source: conversation grill 2026-07-25 · `/to-spec`  

---

## Problem Statement

照护者在编辑睡眠（以及其它由起止时刻构成的区间记录）时，会先选好「睡下 / 醒来」或「开始 / 结束」两个时间点，再点保存或确认。当前半屏录入里 **没有在确认前明确预览这段区间有多长**，用户只能心算，或保存后到时间轴摘要里才看到「时长 …」。

同时，区间不合法时（结束不晚于开始、选了未来时刻、尚未选结束等），确认按钮往往仍可点，要等点击后才在底部报错，反馈偏晚。把「合法时长一眼可见」和「不合法不能存」做成同一套保存前体验，才能减少误记和反复改时间。

## Solution

在快记 / 编辑半屏中，对所有 **起止时刻区间** 记录（睡眠 + Interval，如散步）：

1. 当草稿已具备可解释的起止关系时，在 **起止时间控件正下方** 预览持续时间，文案与时间轴/列表摘要一致（`时长 X小时Y分` / `时长 不足1分`）。
2. 当区间未完成或不合法时，同一位置显示 **短警示文案**，并 **禁用确认/保存**，直到区间合法。
3. 将起止相关错误文案统一为短句表；睡眠圆盘因「结束 ≤ 开始」拒收时，短句之外可附跨天操作指引。
4. 将「校验失败则禁用确认」提升为 **全类型草稿** 规则；非区间类型在底部错误区解释原因，且错误文案遵循「打开不吼、脏了或点过确认再显示」。

不改数据模型、不改异常睡眠软标记规则、不把手填分钟类字段（母乳左右分、配方奶 `duration_min`）纳入「区间预览」。

## User Stories

1. As a 照护者, I want 在改完睡下和醒来时刻后立刻看到时长, so that 我不用心算就能确认这段睡眠是否合理  
2. As a 照护者, I want 时长文案和保存后时间轴上看到的一致, so that 我不会怀疑「预览和最终记录不是一回事」  
3. As a 照护者, I want 在确认醒来时边调醒来时刻边看睡了多久, so that 我能快速决定要不要再微调  
4. As a 照护者, I want 打开「同时记醒来」补记一整段睡眠时也能看到时长, so that 补记和编辑体验一致  
5. As a 照护者, I want 仅确认睡下（进入进行中）时不要被时长预览打扰, so that 界面只服务「现在睡下」这一动作  
6. As a 照护者, I want 编辑进行中、尚无醒来时刻的睡眠时不显示虚假时长, so that 我不会把「进行中」误当成已完成区间  
7. As a 照护者, I want 编辑散步等 Interval 记录时同样看到起止时长, so that 所有区间类型行为统一  
8. As a 照护者, I want 未选择结束时刻时在时间控件下看到简短提示, so that 我知道还要补哪一步  
9. As a 照护者, I want 结束不晚于开始时看到「醒来须晚于睡下」或「结束须晚于开始」, so that 我能立刻改对哪一端  
10. As a 照护者, I want 选了未来时刻时看到「不能选未来时刻」, so that 我不会留下未发生的记录  
11. As a 照护者, I want 区间不合法时确认按钮不可点, so that 我不会点了才发现存不进去  
12. As a 照护者, I want 区间恢复合法后确认立刻可点, so that 修好时间就能保存  
13. As a 照护者, I want 睡眠跨天选错日期导致结束被拒时，除了短错误还有「先改次日」的指引, so that 我知道跨夜该怎么操作  
14. As a 照护者, I want Interval 选错起止时只看到短句、不被跨天文案打扰, so that 散步等场景保持简洁  
15. As a 照护者, I want 圆盘拒收非法结束时草稿保持上一次合法值, so that 预览不会突然变成错误数字  
16. As a 照护者, I want 改开始时刻后时长预览跟着草稿更新, so that 我看到的是将要保存的区间  
17. As a 照护者, I want 极短合法区间显示「时长 不足1分」, so that 不足一分钟也有明确说法  
18. As a 照护者, I want 母乳/配方奶手填分钟不要多出一层「区间预览」, so that 已经手填的时长字段不会重复吵我  
19. As a 照护者, I want 任意类型草稿校验失败时确认按钮灰掉, so that 全局「不能存就不让点」一致  
20. As a 照护者, I want 非区间类型在底部看到不能保存的原因, so that 灰按钮不会变成哑谜  
21. As a 照护者, I want 新建表单一打开若默认还不合法时不要立刻红字骂我, so that 母乳默认 0+0、空日记等场景不吓人  
22. As a 照护者, I want 我改过字段或点过一次确认后再看到错误文案, so that 提示出现在我需要的时候  
23. As a 照护者, I want 区间「未选结束」在时间下始终有短提示（不依赖底部红字）, so that 空结束控件自己说清楚  
24. As a 照护者, I want 取消在校验失败时仍可点, so that 我随时能放弃编辑  
25. As a 照护者, I want 删除不因当前草稿区间非法而禁用, so that 我仍能删掉整条错误记录  
26. As a 照护者, I want 保存中/删除中时操作区保持现有忙碌态, so that 不会重复提交  
27. As a 照护者, I want 区间非法时底部不要再重复同一句时间下警示, so that 屏幕上只有一处主解释  
28. As a 照护者, I want 预览不要提示「偏短/偏长」异常软标记, so that 这次改动只解决时长可见与能否保存  
29. As a 照护者, I want 从时间轴点进已完成睡眠编辑时一打开就看到现有时长, so that 我先知道现在记的是多久再决定改不改  
30. As a 照护者, I want 醒来确认打开时若已有默认醒来时刻就直接显示时长, so that 默认「现在醒来」路径零额外操作  
31. As a 照护者, I want 校验与预览、圆盘失败提示共用同一套短文案, so that 同一错误不会有三套说法  
32. As a 开发者 agent, I want 可测行为集中在快记草稿接缝, so that 不必为布局细节写脆弱 UI 测试  
33. As a 照护者, I want 合法预览随起止变更实时更新（确认圆盘后）, so that 每次改时间都有即时反馈  
34. As a 照护者, I want 记录时刻本身在未来时也不能确认, so that 单点时刻与区间结束遵守同一「不能选未来」原则  
35. As a 照护者, I want 备注等其它字段非法时同样灰确认（全局规则）, so that 不会只修了区间却漏了其它必填  

## Implementation Decisions

### 范围与术语

- **区间记录**：快记模式为睡眠（`Sleep`，含睡下 / 醒来 / 手动完整区间）以及 Interval（当前如散步）。由 `timestamp` + `endTimestamp` 表达起止。
- **非范围**：母乳左右分钟、配方奶等 `duration_min` 手填字段、异常睡眠 `!` 软标记、数据模型 / Room / 同步、列表与日汇总的展示算法重写（仅要求预览文案与既有列表时长说法对齐）。

### 预览出现条件

| 草稿状态 | 时长预览 |
|----------|----------|
| 编辑已完成区间（两端都有且可解释） | 显示 |
| 补记整段（如睡眠「同时记醒来」且已有结束） | 显示 |
| 确认醒来（开始可只读，结束可调；结束已设） | 显示 |
| 仅确认睡下（结束为空，合法进入进行中） | **不显示** |
| 进行中 / 结束为空且业务要求必须有结束 | **不显示合法时长**；时间下显示「请选择醒来/结束时刻」类短提示 |
| 两端存在但区间非法 | 时间下显示短警示，不显示误导性时长数字 |

### UI 位置与文案

- **位置**：起止时间控件区块正下方（不是标题区，也不是仅贴在确认按钮旁）。
- **合法文案**：与列表摘要一致——`时长 {formatDuration}`，其中不足 1 分钟为 `时长 不足1分`；小时/分钟组合规则与现有记录展示相同。
- **非法 / 未完成短文案表**（校验、预览位、圆盘失败主句共用）：

| 情况 | 睡眠 | Interval |
|------|------|----------|
| 未选结束 | 请选择醒来时刻 | 请选择结束时刻 |
| 结束 ≤ 开始 | 醒来须晚于睡下 | 结束须晚于开始 |
| 结束在未来 | 不能选未来时刻 | 不能选未来时刻 |
| 开始/记录时刻在未来 | 不能选未来时刻 | 不能选未来时刻 |

- **跨天（仅睡眠圆盘）**：当因结束 ≤ 开始拒收选时，主句用上表短句，并 **附加** 操作指引：`跨天请先把日期改为次日`（Interval 不附）。该指引不是第二套合法性定义，只帮助跨夜操作。
- **异常时长软提醒**：本次 **不做**（不在预览下附加偏短/偏长）。

### 确认按钮与全局校验态

- **全局规则**：任意类型快记草稿在 `validationError != null` 时，主确认/保存按钮 **disabled**（仍受保存中/删除中等忙碌态约束）。
- **取消**：始终可点（非忙碌时）。
- **删除**（编辑态）：不因草稿校验失败而禁用。
- **原因展示**：
  - 区间类：时间下预览/警示为主；区间非法时底部 **不重复** 同一句。
  - 非区间类：底部错误区展示 `validationError`。
- **展示时机（避免一打开就骂人）**：
  - 确认按钮：非法时 **立刻** disabled。
  - 非区间底部错误文案：仅在草稿已「脏」（用户改过相关字段）或用户 **点过一次确认** 后显示。
  - 区间「未选结束」：时间下短提示可 **始终** 显示（控件空态），不依赖底部红字策略。

### 模块与接口（逻辑层，不锁文件路径）

- **主改动面**：快记草稿模型 + 快记半屏时间字段区 + 确认按钮 enabled 绑定。
- **草稿对外应能表达**（命名可调整，语义需具备）：
  - 区间预览内容：合法时长文案 / 短警示 / 无（仅睡下等）
  - `validationError`：全类型短文化后的统一校验
  - 是否允许确认：与「无 validationError 且非忙碌」一致
  - 是否展示校验文案：`showValidation`（或等价：dirty ∨ attemptedConfirm）；区间空结束的时间下提示可独立于该旗标
- **时长格式**：复用与列表摘要相同的持续时间格式化规则，禁止草稿与列表各写一套不一致的小时/分钟文案。
- **改开始时刻**：保持现有「有结束则平移结束、尽量保持时长」的交互；预览只反映更新后的草稿，不另发明时间语义。
- **圆盘拒收非法值**：不把非法结束写入草稿；草稿保持上一合法状态，主句/附加指引按上文。
- **无 schema / API / 同步契约变更**。

### 交互细节补充

- 醒来路径若打开时已带默认结束时刻（如点击时刻），应直接显示合法时长且确认可点（在其它字段也合法的前提下）。
- 合法预览在用户确认新的起止时刻后立即更新。
- 忙碌文案（保存中… / 删除中…）行为保持现有，不与预览文案混淆。

## Testing Decisions

### 什么叫好测试

- 只断言 **对外行为**：给定草稿起止与动作（dirty / 尝试确认），得到预览文案、校验文案、是否可确认、是否应展示错误。
- 不测 Compose 布局像素、不测内部 private 重组细节、不测 Room。
- 文案断言用已定短句表与 `时长 …` 规则，避免绑死具体 Composable 结构。

### 主接缝（唯一）

**快记草稿（Quick Record Draft）** —— 扩展现有草稿单测传统（已有校验、确认文案、起止、序列化用例）。

应覆盖至少：

1. 完整睡眠区间 → 合法 `时长 …` 预览语义  
2. 仅睡下、结束为空 → 无时长预览，且校验通过（可确认睡下）  
3. 醒来 / 手动完整 / 同时记醒来有结束 → 有预览  
4. 结束 ≤ 开始、结束在未来、未选结束（对需要结束的动作）→ 短文案表 + 不可确认  
5. Interval 与睡眠分词正确  
6. 不足 1 分钟 → `时长 不足1分`  
7. 全局：母乳 0+0、空日记等 → 不可确认；`showValidation` 在未 dirty 未尝试确认时为 false，dirty 或尝试确认后为 true  
8. 文案短句与旧长句不再作为期望（测试更新到新表）

### Prior art

- 既有草稿单测中的 `validationError` / `confirmLabel` / 睡眠起止用例风格  
- 列表侧已有持续时间展示规则（预览应对齐其对外字符串规则，而非复制无关 UI）

### 非主接缝

- UI 绑定可选极少 smoke；**不作为交付门禁主接缝**  
- 不新增 domain/同步测试要求  

## Out of Scope

- 异常睡眠时长软提醒 / 时间轴 `!` 规则调整  
- 母乳计时器、配方奶手填 `duration_min` 的「第二预览」  
- 跨天日期选择器本身的交互重做（仅保留拒收时的指引句）  
- 数据模型、迁移、同步 outbox、小组件  
- 把所有历史长错误句全产品统一（本次聚焦区间相关 + 与确认态相关的草稿校验展示；其它类型可继续用其现有校验句，除非实现时顺手共享「不能选未来时刻」等已定共用句）  
- 无障碍专项（TalkBack 文案细化）可作后续，不阻塞本 spec  
- 视觉动效、插画、新建设计系统组件库扩展（可用现有文字样式）  

## Further Notes

- 本需求经 grill 收敛：类型范围 B（全部起止区间）、路径 1/2/3 显示、位置贴时间下、合法文案对齐列表、非法 B 短句 + 锁确认、异常软提醒不做、未选结束时间下提示 + 锁确认、短文案表定稿、睡眠圆盘拒收附跨天指引、确认锁定全局、错误展示分区 + 打开不吼。  
- 测试接缝经用户确认：**草稿为唯一主接缝**。  
- 实现时若发现「全局一打开就 disabled」与某些默认合法草稿冲突，以「默认草稿应尽量合法」为辅、以「B：立刻灰、文案延后」为主，不回退到点击后才校验。
