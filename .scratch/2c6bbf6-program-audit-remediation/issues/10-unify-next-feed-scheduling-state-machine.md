# 10 — 统一下次喂养安排状态机

**What to build:** 让普通喂养 Composer 与护理计时完成流程共用一套“是否安排下一次、何时安排、保存中及失败恢复”状态机。

**Blocked by:** None — can start immediately

**Status:** complete

**Size:** M

## Acceptance criteria

- [x] 两个入口都在事实记录确认后提供一致的“不安排”和“安排下一次”选择，用户不会被困在必须创建计划的流程里。
- [x] 选择安排时使用同一日期/时钟输入、未来时间校验和默认建议；选择不安排时不会残留候选计划。
- [x] Record 与可选 CarePlan 的保存边界明确：重复点击、重组或回调重入不会产生重复事实或重复计划。
- [x] 保存中有一致忙碌状态；失败时明确指出事实与计划各自是否成功，并提供不会重复写入的恢复动作。
- [x] 取消安排提示可安全回到已完成事实，不删除或篡改刚保存的 Record。
- [x] 两个入口的状态机测试覆盖不安排、安排、非法时间、重复提交、部分失败与重试，并断言输出等价。

## Validation

运行 RecordComposer、护理计时、CarePlan 与状态恢复测试，以及应用编译和静态检查；设备 smoke 两种入口。

## Documentation Gate

把“事实已发生”与“未来安排可选”的共同交互写成单一 PRD 契约。
