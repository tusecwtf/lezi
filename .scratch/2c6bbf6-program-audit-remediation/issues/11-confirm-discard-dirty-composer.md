# 11 — 脏 Composer 草稿放弃确认

**What to build:** 当 RecordComposer 中存在用户改动时，所有退出方式都先确认继续编辑或放弃；放弃只清理该草稿新导入的资源。

**Blocked by:** 01 — 履行草稿保护计划原图

**Status:** complete

**Size:** M

## Acceptance criteria

- [x] 草稿相对初始预填值发生字段、时间、照片或自定义项变化后被判定为 dirty；未改动时可直接退出。
- [x] 系统返回、顶部关闭、手势关闭和其他可达退出路径对 dirty 草稿显示同一确认对话框。
- [x] “继续编辑”完整保留字段、照片顺序、校验提示与当前输入焦点所需状态。
- [x] “放弃”关闭 Composer，并只删除本草稿新导入且没有其他活跃引用的临时照片。
- [x] 计划预填照片、已有 Record 照片及其他实体共享文件在放弃时保持完整。
- [x] 保存进行中不能通过放弃流程造成半写入；成功保存后退出不再提示未保存更改。
- [x] 状态恢复和 Compose 测试覆盖各种退出入口、继续、放弃、保存中与进程重建。

## Validation

运行 Composer 状态/导航/照片测试与应用编译；设备上验证返回键和关闭按钮的相同行为。

## Documentation Gate

如产品文案新增“放弃草稿”，同步更新交互规格与本地化资源。
