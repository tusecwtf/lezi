# 02 — 按活跃引用回收共享照片文件

**What to build:** 删除或编辑 Record/CarePlan 的照片时，先按活跃媒体引用判断物理文件是否仍被其他实体使用；只有最后一个活跃所有者消失后才回收文件。

**Blocked by:** 01 — 履行草稿保护计划原图

**Status:** ready-for-agent

**Size:** M

## Acceptance criteria

- [ ] 计划履行后，计划与事实 Record 可安全引用同一份本地照片字节。
- [ ] 从 Record 移除照片或删除 Record 时，若计划仍有活跃引用，物理文件不会被删除。
- [ ] 从计划移除照片或删除计划时，若 Record 仍有活跃引用，物理文件不会被删除。
- [ ] 最后一个活跃引用删除后，物理文件只在没有待上传/暂存消费者时回收；媒体 tombstone 与 Outbox 元数据仍按远端确认契约保留，不能因本地无主而提前删除。
- [ ] 缺失文件、陈旧本地 URI 或重试中的媒体状态不会导致崩溃；可下载的远端媒体能按既有恢复规则修复。
- [ ] 回收判断覆盖普通编辑、整实体删除、履行共享和同步 tombstone，不依赖调用入口碰巧正确。
- [ ] 物理删除 I/O 失败或进程在回收中断时不发布虚假完成；重启后能安全重试并最终收敛，且不会重复发送或丢失远端删除意图。
- [ ] 回归测试使用真实临时文件建立双引用、删一留一、删尽回收、暂存上传、删除失败/重启与缺失文件场景。

## Validation

运行媒体仓储、Record/CarePlan 编辑删除、同步恢复相关测试以及应用编译和静态检查。

## Documentation Gate

把“媒体行所有权”与“物理文件所有权”的区别写入数据模型或同步契约文档。
