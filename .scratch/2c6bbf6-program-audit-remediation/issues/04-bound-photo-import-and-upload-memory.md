# 04 — 限制照片导入与同步上传内存

**What to build:** 对照片导入和同步上传实施 MIME、字节数、像素数及批次预算，使用有界流式处理，避免把多个原始文件无上限地一次性读入内存。

**Blocked by:** 03 — 统一有界、后台图片解码

**Status:** complete

**Size:** M

## Acceptance criteria

- [x] 导入前后都校验允许的 MIME、单文件字节上限与解码像素上限，伪装扩展名不能绕过检查。
- [x] 0–3 张照片的复制、规范化与上传采用有界缓冲或流式路径，不对原始大文件执行无界整文件读取。
- [x] 批量导入中任一文件失败时，草稿状态与已创建临时文件按原子语义回滚或保留为明确可重试状态。
- [x] 上传重试不会同时保留多份完整字节副本；取消同步能及时释放流和缓冲区。
- [x] 超限、损坏或不支持的图片给出用户可理解且可恢复的错误，不导致 Composer 或同步进程闪退。
- [x] 自动化测试覆盖边界值、超限值、三图批次中途失败、取消与重试，并有可检查的峰值内存边界证据。

实现与验收收据见 [`../evidence/04/bounded-photo-import-upload.md`](../evidence/04/bounded-photo-import-upload.md)。

## Validation

运行照片导入、媒体上传和同步重试测试，以及 Android 编译和静态检查；设备 smoke 使用接近上限的三张图片。

## Documentation Gate

在产品/同步文档中写明支持格式和资源上限；数值由单一配置源给出，避免文案与实现漂移。
