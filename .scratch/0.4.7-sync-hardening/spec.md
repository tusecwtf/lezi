# 0.4.7 同步加固

## Problem Statement

0.4.5 事故（工单 `.scratch/0.4.5-sync-stuck-remediation/`）里，姥姥的设备在一次全量家庭对账中把
「页内存在引用未就绪实体」当作致命错误：整页回滚、拉取 cursor 冻结、本机事实停在待同步、
睡眠合计按「开放至今」膨胀，家人以为应用坏了。0.4.6 的有界跳过已让设备重新收敛，但留下三个
用户可感的问题：

1. **失败无名**：引擎里每个引用门只返回「没成」，不说是哪个门、什么本机状态判的——8-29 的
   真实门至今没有被指认，下一次复发还得靠装机取证。
2. **跳过即静默缺失**：3 次重投后永久跳过只留一条本地回执；任何家人设备触发全量重对账踩中
   同一个门时，家庭事实会无声地从那台设备的时间轴消失。
3. **缺口不可见**：回执只投影最早一条「家里没收下」，家人无法知道有多少项、是哪些没收到。

## Solution

0.4.7 客户端加固（零 wire 改动、零服务端改动）：

- 每次拉取应用失败都**具名**：哪个门、缺哪个引用、当时本机什么状态，随回执持久化——第一次
  复发即自证，不再需要诊断装机轮次。
- 用事故原始三页在引擎测试台架上**重放定位真门**并修掉它，让「3 次后跳过」这个兜底在结构上
  不应再被触发。
- 台账寿命绑定 cursor 寿命：重装/重登/被移除后重加（cursor 归零）时清空重试计数，被跳过的
  键随全量重走自然重投——**跳过自愈**。
- 状态行聚合显示「N 项未收下」并提供明细入口；主状态保持「已同步」不降级——**缺口可见而不
  恐慌**。

## User Stories

1. 作为家庭成员，我想在账户概览的同步状态行看到「N 项未收下」的聚合提示，以便知道本机有
   家庭事实缺口需要处理。
2. 作为家庭成员，我想点进「未收下」明细看到每项的记录类型、短标识与发生时间，以便告诉管理员
   或对照他人设备定位缺了什么。
3. 作为家庭成员，我想在存在被跳过项时状态行仍显示「已同步 · 刚刚」，以便不误以为同步又坏了、
   重演 0.4.5 的恐慌循环。
4. 作为家庭成员（姥姥设备的实际使用者），我想在重装、重新扫码加入或被移除后重加时，此前被
   跳过的家庭事实随全量重对账自动重投，以便换机/重登后时间轴完整。
5. 作为家庭成员，我想让被跳过项的明细随下一轮成功拉取自动清账（新洞才存活），以便状态行
   不积累陈旧噪音。
6. 作为家庭管理员，我想在家人报告「未收下」时，从同一明细入口看到具名原因（哪个门、缺哪个
   引用），以便向开发者一次说清而不是反复截图猜。
7. 作为家庭管理员，我想让普通成员设备的加固不需要任何服务端升级，以便全家只升 APK 就完成
   部署。
8. 作为本机有待对账修改的成员，我想让引用门的具名化不改变 commit-first 发表语义（ADR-0022），
   以便本机事实的权威证明路径不受影响。
9. 作为本机有待对账修改的成员，我想让同步收敛周期照常完成（跳过不阻塞 cursor 推进），以便
   待同步归零的判据不变。
10. 作为离线后恢复的成员，我想让依赖跨轮迟到的实体仍享受同轮二次机会与最多 3 次重投，以便
    网络恢复后数据自动补齐（兜底行为不回退）。
11. 作为乐记维护者，我想让每个引用门失败时必须携带具名原因（编译器强制），以便任何未来新增
    的门都无法静默返回失败。
12. 作为乐记维护者，我想让 `reference_unready` 回执携带门名、缺失引用与本机状态快照，以便
    一次复发就是一份自证根因报告，替代出诊断版装机取证。
13. 作为乐记维护者，我想用事故原始三页在引擎台架重放（member 角色、全新本机库），以便要么
    点名并修掉真门，要么确证「台架不可复现」并把根因交给复发自证。
14. 作为乐记维护者，我想让重放断言从「无未解析」升级为「未解析必须携带已知清单内的原因」，
    以便测试从黑盒变白盒、状态注入矩阵从原因定义反推。
15. 作为乐记维护者，我想让结构性洞（服务端确认不下发）与状态性误判（本机状态导致）在原因
    上可区分，以便将来按类分流策略（永久跳过 vs 退避重试）有依据。
16. 作为乐记维护者，我想让台账在 cursor 归零时清空（台账寿命=cursor 寿命），以便计数不跨
    世代泄漏、同键新 revision 不继承陈旧计数。
17. 作为乐记维护者，我想让跨页幂等重发、单点 cursor 发布、回持等 0.4.6 已验证行为全部保持
    （专项测试全绿），以便加固不回退止血。
18. 作为乐记维护者，我想让提交进仓库的重放夹具是结构等价的合成语料（不含真实家庭数据），
    以便遵守「不提交真实家庭数据」的红线同时保留回归价值。
19. 作为乐记维护者，我想让 3 次上限保持不变，以便在没有新证据前不引入时间维度重试的复杂度。
20. 作为乐记维护者，我想让两个测试缝隙（引擎同步入口、状态行投影）承载全部新断言，以便
    缝隙数量不膨胀、测试持续可维护。

## Implementation Decisions

- **模块**：`sync`（引擎判决、台账、回执、状态行投影）；`core/database`（`PullDiagnosticReceipt`
  编解码扩展）；账户概览面（明细入口展示，消费投影数据）。不触及 `tools/lezi-sync`、wire、
  Room schema 之外的任何服务端契约。
- **密封判决**：拉取应用树的门判定从布尔返回改为密封类型（`Applied` / `Deferred(reason)`）；
  `DeferredReason` 至少携带：门名（如 宝宝缺失/自定义项目缺失/睡眠类型不符/醒来改绑/计划引用
  不完整/履行集合不完整/媒体编辑守卫…）、缺失引用（类型+client_uuid）、当时本机状态快照。
  布尔 `false` 从该树中消失，由编译器保证穷举具名。
- **回执升级**：`reference_unready` 回执增加原因字段；仅本机 Room 存储，零 wire 字段、零服务端
  改动。轮首清陈旧回执、本轮新洞存活的既有节奏保持。
- **重放定位**：以事故库只读副本重放出的真实三页（0→283 / 283→491 / 491→770）作为一次性台架
  输入（member 角色、全新库）；提交物是**结构等价合成语料**（保留墓碑成对、rev 序、页外父
  实体重发、醒来洪泛等结构，替换全部真实标识/时间/备注）。真门被点名即随修复附回归测试。
- **台账自愈**：重试台账（transport journal 单键）在拉取 cursor 归零（重装/重登/重加）时整体
  清空；不做按代际、按升级的触发。
- **重试上限**：每 cursor 世代保持 3 次；原因分流（结构性洞永久跳过 / 状态性误判退避重试）
  仅在重放或复发给出证据后作为后续工单，不在本期实现。
- **可见性**：状态行新增独立警告行「N 项未收下」（聚合数来自回执投影）；明细入口按 类型/短
  标识/时间 列出；主状态（已同步/待同步/错误）判定不因跳过项改变；不做时间轴占位符、不做
  手动「重试被跳过项」按钮。
- **词汇对齐**（CONTEXT.md）：聚合行属于「同步状态（概览）」的一句话人话约束；跳过项是
  「家庭事实」在本机副本的缺口，不是待对账修改；自愈发生在「家庭对账」的全量路径。

## Testing Decisions

- **好测试的标准**：只在外部行为上断言——缝隙 1 断言 synchronize 之后的可观察结果（Room 行、
  cursor、回执内容），缝隙 2 断言投影纯函数的输出；不断言私有调用序，唯一结构性断言是
  「未解析必须携带已知清单内的原因」这一公开契约。
- **缝隙 1（引擎）**：`ReplicaSyncEngine.synchronize` × `ReplicaEngineRig`。先例：
  `ReplicaSyncEngine*Test` 全家（睡眠/醒来数据流、因果收敛、创作者回执、来源关系）。
  新增：每个 `DeferredReason` 可构造且可被引擎产出（原因清单穷举测试）；重放合成语料的
  收敛/点名测试；cursor 归零清台账的重登场景测试。
- **缝隙 2（投影）**：`projectShallowSyncLine` / `ShallowSyncFacts` 纯投影。先例：
  `ShallowSyncStatusProjectorTest`、`RealSyncPortShallowStatusTest`。新增：N 项聚合行、
  主状态不降级、明细投影（类型/短标识/时间）的判定与优先级测试。
- **不新增缝隙**：不为可见性开 UI 测试缝；不为台账开 DAO 直测缝（经缝隙 1 的重登场景覆盖）。

## Out of Scope

- 服务端 Rust 任何改动（本次事故已定案服务端无缺陷；NAS 保持 0.4.5/schema 13）。
- wire 协议、Room schema 版本、本地数据契约版本的变化。
- elder 适配与 0.4.6 重出（已定稿归 0.4.6 发布轨道，见 `.scratch/0.4.7-sync-hardening/plan.md`
  发布修订节）。
- 时间维度重试上限、按原因分流的差异化策略（等重放/复发证据）。
- 时间轴缺口占位符、手动重试入口。
- VPS/DNS（ticket 03 前置）与 NAS 渠道替换操作。
