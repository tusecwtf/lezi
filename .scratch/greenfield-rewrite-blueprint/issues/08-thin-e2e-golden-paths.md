# 08 — 薄 E2E 金线路径清单

**Type:** grilling  
**Status:** resolved  
**Blocked by:** 01

## Question

选定**最少**端到端用户路径作为功能一致金线（本机 APK + 本机后端），明确每条路径的前置、步骤、可观察成功条件，以及明确不进金线的表面。目标是可回归、可维护，不是穷尽。

## Constraints from map

- 行为真相：PRD/ADR/CONTEXT + 本金线；旧巨型单测不当合同
- 输入： [01 — 产品表面与行为合同清单](./01-product-surface-inventory.md)

## Answer

### 总则

| 项 | 规则 |
|----|------|
| 环境 | 本机绿场 APK（`com.lezi.babylog.gf`）+ `greenfield/sync-server`（HTTPS **18765**，数据 `greenfield/.data`）；**禁止**默认家庭 NAS |
| 断言 | **可观察用户结果**（UI/本地数据可见性）；不断言 wire 字段、内部 mutex、Store 算法 |
| 双端 | 需要时两台模拟器/两用户数据目录，同一本机 server |
| 覆盖目标 | inventory [§5 skeletons](../assets/01-product-surface-inventory.md) 的**子集**，非穷尽 |

### 必绿金线（10）

| ID | 名称 | 前置 | 步骤（用户可见） | 成功条件（可观察） |
|----|------|------|------------------|-------------------|
| **G1** | 离线记账 | 未加入家庭；空/新安装 | 建宝宝 → 配方/尿/睡眠等确认写入 → 日条/汇总可见 → 杀进程恢复 | 记录仍在；打开入口未写库；无强制在线 |
| **G2** | 计时→下次喂养 | 有宝宝 | 开喂奶计时 → 完成确认 → 可选安排下次喂养 → 待履行区可见 → 履行 | 一条护理记录；计划状态正确；确认前无落库 |
| **G3** | 建家 | 本机空 server；根密码已知 | 可信 HTTPS/TOFU → probe empty → 根密码建家 → 账户为 Owner | 家庭名/本人称呼可见；可同步 |
| **G4** | 申请加入 | Owner 已建家；第二设备 | 成员申请 → Owner 批准 → 成员取得会话 → 拉历史 | 成员账户态正确；能见家庭数据 |
| **G5** | 跨端原子记录 | 两设备已入同一家庭 | A 写记录+照片并前台同步 → B 同步 | B **同时**见记录与照片（无半包）；非仅元数据 |
| **G6** | 跨端计划履行 | 两设备已入家 | A 建计划 → B 本地提醒独立 → 任一方履行 | 全家一份完成事实；他端收敛 |
| **G7** | ACL | Owner+Member 已入家 | Member 尝试删/改他人记录；Owner 操作 | Member 被拒或不可用；Owner 可；结果可观察 |
| **G8** | 网络/身份 | 已加入；可改本机 server 配置 | 同 family 改地址仍可；错误 family/SPKI 变更 | 同家可恢复；错家/证书变更 **阻断** 并有说明 |
| **G9** | 应用更新壳 | 本机 mock 更新元数据 | 可选更新可见；强制更新挡主路径；未加入诚实 | 壳与文案符合 PRD；不依赖生产分发 |
| **G10** | 退出/离开 | 已加入 | 退出设备 / 离开家庭（角色允许的路径） | 会话清除；本地家庭数据按合同清空或保留策略可见正确 |

### 明确不进必绿金线

| 表面 | 处理 |
|------|------|
| J-JOIN-QR / 真机相机 / 邀请首装页 | 人工抽样；非 CI 必绿 |
| J-RESTORE 空服灾难恢复 | 人工 / 专项 |
| J-EXPORT-SEARCH、J-LAYOUT 跨端不共享、J-WIDGET、J-GROWTH 细百分位 | 单测或人工 |
| 物理 NAS、生产 CD、双真机发布门 | 地图 out of scope / 发布门，非绿场金线 |
| 旧巨型 `RealSyncPortTest` / `api.rs` 1:1 | 禁止作合同 |
