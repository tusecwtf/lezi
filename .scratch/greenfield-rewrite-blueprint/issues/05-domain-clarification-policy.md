# 05 — 领域澄清式修订政策

**Type:** grilling  
**Status:** resolved  
**Blocked by:**

## Question

「允许澄清式修订 CONTEXT/ADR」的边界是什么：哪些术语/不变量默认冻结，何种证据才允许改术语或收紧/放宽不变量，以及重写期间 domain-modeling 的工作流（何时改 CONTEXT、何时写 ADR）。

## Constraints from map

- 不是借重写做新产品
- 用户可见行为与 UI 合同仍须成立

## Answer

### 默认冻结的不变量（改语义 = 新产品，不在本努力）

实现与 wire **表达**可换；下列**语义**不可借绿场改掉：

| 域 | 冻结要点 |
|----|----------|
| 核心照护 | 护理记录 ≠ 护理计划；确认后写入；计划履行 / 履行候选证据 / 冲突未采纳履行等 CONTEXT 关系 |
| 家庭身份 | membership ≠ 凭证；唯一管理员；设备可撤销；称呼/角色归属 membership |
| 原子同步 | 记录/计划与其照片为原子同步单元；接收方不暴露半包 |
| 同步意图 | 本地优先；家庭同步域全量共享（不按人过滤可见性）；前台触发同步的产品意图（非「必须用现 RealSyncPort API」） |

### 澄清门槛（须满足「证据三选一」且不改用户可见合同）

**允许**当且仅当下列之一成立，且结果仍通过 PRD/UI/E2E 金线：

1. **文档互斥**：多份权威文档矛盾 → 以**更新的** PRD / 同步合同（如 `sync-trusted-endpoint.md`）为准对齐旧表述  
2. **术语≠已交付行为**：CONTEXT/ADR 措辞与真实已交付行为不一致 → 以行为 + 金线为准改术语/收紧歧义  
3. **实现细节污染术语表**：把协议字段、模块名、临时策略写进 CONTEXT → 移出 CONTEXT，必要时进 ADR/PRD  

**禁止：**

- 借「澄清」加功能或改产品范围  
- 放宽安全/权限/身份模型  
- 改动上表冻结语义（那是新产品努力）  
- **放宽**不变量「图省事」；**收紧**仅用于消除歧义且金线仍过  

### 工作流（落文件）

| 内容 | 落点 |
|------|------|
| 术语 / 概念边界 | 根 `CONTEXT.md`（无实现细节） |
| 难反转、惊人、有真实取舍的架构决定 | `docs/adr/NNNN-….md` |
| 用户可见能力与验收 | `docs/prd/`（含 `ui.md`） |
| 过程票与蓝图 | `.scratch/…`（**不是**第二套长期产品真相） |

规则：澄清**当次**改对应权威文件；绿场写代码前若触及不变量，**先合文档再实现**。不维护绿场私有 CONTEXT 分叉到 cutover。

### 已知漂移（政策示例，本票不改文档）

| 漂移 | 澄清方向（示例） |
|------|------------------|
| `data-model.md` 仍写硬家网 Wi‑Fi | 以 `sync-trusted-endpoint.md` 当前合同为准（可信服务器身份，非 SSID） |
| `ui.md` 残留「共享码/停止共享」等旧文案 | 以当前账户 IA / trusted-sync UI 设计为准 |

实际改文档：另开小任务或蓝图实现前批量对齐，**不在本票执行**。
