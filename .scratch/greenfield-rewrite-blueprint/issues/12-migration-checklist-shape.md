# 12 — 将来切换：原则与可执行清单形态

**Type:** grilling  
**Status:** resolved  
**Blocked by:** 07

## Question

在「开发期禁止生产 CD」前提下，蓝图对**将来某次**旧→新切换应写清的原则与可执行清单条目（迁什么数据、APK/服务端顺序、失败回滚意图、谁触发），明确不写生产 runbook/CD 命令。

## Constraints from map

- 数据可迁；无长期双协议
- 不写 NAS 生产演练脚本

## Answer

### 原则

| 项 | 决定 |
|----|------|
| 形态 | **维护窗 cutover**：新栈 fresh + **数据映射导入** + **会话重建** |
| 协议 | 一次切到新 current；**无**长期双协议 / 双写 |
| 凭证 | 旧 access/refresh **不**迁到新 wire；设备重新 TOFU/登录/批准 |
| 语义 | 遵守 [05](./05-domain-clarification-policy.md) / [07](./07-wire-and-schema-redesign-principles.md) 映射 |
| 角色 | **Owner** 表达切换意图；**运维**在独立努力中执行窗（本地图仍 **禁 CD**） |
| 深度 | 蓝图含原则 + **清单章节骨架**；具体映射行与命令在实现后期 / 切换项目填写 |
| 禁止写入蓝图 | `ssh`/`docker`/`push-and-deploy` 生产命令、密钥、真实家庭数据 |

### 推荐顺序（意图级）

1. 本机/隔离环境：新 server 空实例 + 映射演练通过  
2. 维护窗：准备新服务端数据（导入映射结果），验证 health/capability  
3. 客户端换装绿场/新 applicationId 或正式接替包（切换项目定）  
4. 全员**重建会话**（Owner 根密码/成员再批准）  
5. 用 G* 子集做成功判据  
6. 旧 wire/旧容器仅在回滚需要时保留，成功后退役  

### 清单必须章节（蓝图模板）

1. **范围与冻结语义** — 迁什么 / 不迁什么（产品）  
2. **实体映射表** — 旧实体 → 新语义 ID/字段，或「不可迁 + 用户影响」  
3. **媒体与原子包** — bytes 与记录/计划绑定完整性  
4. **服务端顺序** — fresh 实例、导入、capability 验证（无 CD 命令）  
5. **客户端顺序** — 安装/数据导入本机、入口切换  
6. **会话与信任重建** — TOFU/SPKI、Owner/Member 路径  
7. **成功判据** — 至少覆盖 G1/G3/G5/G10 类可观察结果（切换项目可扩）  
8. **失败回滚意图** — 何种条件下回到旧栈；前提：旧数据未毁  
9. **明确不做** — 双协议、合并两家庭、本努力内生产 CD  

### 对 13

蓝图「迁移」章 = 上表原则 + 空章节模板；不假装 runbook 已可执行。
